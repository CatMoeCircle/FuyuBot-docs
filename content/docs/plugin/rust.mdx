Rust 插件只依赖一个 crate：[`fuyubot-abi`](https://crates.io/crates/fuyubot-abi)。
它给出 `HostApi`（VTable 的 Rust 封装）、`Plugin` trait、`define_plugin!` 宏与
`ResponseRouter`；**没有第二层 SDK**——写插件就是实现一个 trait，再把 C ABI 导出交给宏。

用 AI Agent 写？本站导出了 `llms.txt` / `llms-full.txt` 和每页的 `content.md`，
怎么喂见[插件总览 › 用 AI Agent 写插件](./index.mdx#用-ai-agent-写插件)。

## 依赖

```toml
# 独立插件 crate：不属于任何 workspace
[workspace]

[package]
name = "fuyubot_demo"
version = "0.1.0"
edition = "2024"
rust-version = "1.99"

[lib]
crate-type = ["cdylib"]          # 宿主 dlopen 的就是它

[dependencies]
fuyubot-abi = "0.1.3"
```

那个空的 `[workspace]` 不是多余的：没有它，cargo 会一路往上找父目录的 workspace 声明然后报错。
`fuyubot-abi` 走**独立版本线**（不跟 bot 的版本号，当前 `0.1.3`）；ABI 契约版本是
`fuyubot_abi::ABI_VERSION`（当前 **6**），编辑器里补全一下就有，别手抄。

## 最小可用插件

```rust
use std::ffi::CStr;

use fuyubot_abi::{HostApi, LogLevel, Plugin, define_plugin};

struct DemoPlugin {
    host: HostApi,
}

impl Plugin for DemoPlugin {
    fn init(host: HostApi) -> Result<Self, String> {
        host.log(LogLevel::Info, "demo: init");
        Ok(Self { host })
    }

    fn start(&mut self, config_json: &str) -> Result<(), String> {
        self.host
            .log(LogLevel::Info, &format!("demo: start({config_json})"));

        // 兜底通道 "update" 收全部；要精确就换成 "updateNewMessage" 之类具体的 @type。
        let handle = self.host.on(
            "update",
            None,
            on_update,
            std::ptr::null_mut(),
        );
        if !handle.is_valid() {
            return Err("订阅 update 失败".to_owned());
        }
        Ok(())
    }
}

extern "C-unwind" fn on_update(
    _user: *mut std::ffi::c_void,
    payload: *const std::ffi::c_char,
) -> i32 {
    // SAFETY: 宿主按 ABI 契约传的是临时 NUL 结尾字符串。
    let text = unsafe { CStr::from_ptr(payload) }.to_string_lossy();
    println!("demo: 收到 {text}");
    0
}

define_plugin!(DemoPlugin, "demo");
```

`define_plugin!(类型, "插件名")` 展开出七个导出符号
（`plugin_init` / `plugin_start` / `plugin_stop` / `plugin_free_string` /
`plugin_free_handle` / `fuyubot_abi_version` / `plugin_manifest`），
并把插件的名字、crate 版本、`inject` / `soft_inject` 填进 `plugin_manifest`。

## `Plugin` trait

| 方法 | 对应符号 | 说明 |
| --- | --- | --- |
| `init(host) -> Result<Self, String>` | `plugin_init` | 构造状态；返回 `Err` = 拒绝加载 |
| `start(&mut self, config_json) -> Result<(), String>` | `plugin_start` | 订阅 / 注册都写在这里；`config_json` 是宿主传来的配置 |
| `stop(&mut self)` | `plugin_stop` | 可选，回收 `Box::into_raw` 之类的状态 |
| `inject() -> Vec<String>` | `plugin_manifest` | 硬依赖：缺了不激活 |
| `soft_inject() -> Vec<String>` | `plugin_manifest` | 软依赖：只影响排队顺序 |

`define_plugin!` 还把 `init` / `start` / `stop` 包在 `catch_unwind` 里——和回调的
`C-unwind` 是两层，**两层都要**：一层防 panic 逃出 ABI，一层防 panic 把宿主线程带走。

## 回调与状态

回调是裸函数指针，没有捕获环境。状态要么放插件字段、经 `user_data` 传进去：

```rust
struct CallbackState {
    host: HostApi,
}

struct DemoPlugin {
    host: HostApi,
    /// `Box<CallbackState>` 的地址；`stop` 时收回。
    state: usize,
}

fn start(&mut self, _config_json: &str) -> Result<(), String> {
    let state = Box::into_raw(Box::new(CallbackState { host: self.host }));
    self.state = state as usize;

    self.host.on(
        "updateNewMessage",
        None,
        on_message,
        state as *mut std::ffi::c_void,
    );
    Ok(())
}

fn stop(&mut self) {
    if self.state != 0 {
        // SAFETY: 指针来自 start 里的 Box::into_raw，只在这里收回一次。
        drop(unsafe { Box::from_raw(self.state as *mut CallbackState) });
        self.state = 0;
    }
}
```

<Callout type="warn">
  订阅句柄**不会**在 drop 时自动退订——`SubscriptionHandle` 只是个 `u64`。
  要提前退订就留住它、调 `host.off(handle)`；插件卸载时宿主会整批回滚，
  但 `user_data` 指向的状态还是得自己释放。
</Callout>

## 登记命令

命令表由宿主提供，在 `start()` 里登记即可，不需要等 `/help`、也不需要 `soft_inject`：

```rust
self.host.call_service(
    "fuyubot.host.commands",
    "register",
    r#"{"name":"hello","description":"打个招呼","role":"user","scopes":["private","group"]}"#,
)?;
```

`role` / `scopes` / `hidden` 的默认值与语义见[命令表与 /help](./command-table.mdx)。
命令回调里回复用 `Command::reply_then`，不要自己拼 `sendMessage`（见[配置文件](../usage/config.mdx)）。

## 读 / 写配置

每个插件在 `fuyubot.toml` 的 `[plugin.<插件名>]` 下有自己的一段（见[配置文件](../usage/config.mdx)）。

<Callout type="info">
  `plugin_start` 收到的 `config_json` **不是**这一段。那是宿主给的运行环境信息
  （`plugins_dir` / `scripts_dir` / `spawn` 等）；你自己的配置用 `get_config("", key)` 读（空 section = 自己那段）。
</Callout>

| 方法 | 作用 |
| --- | --- |
| `get_config(section, key) -> Option<String>` | 读配置。`section` 用**配置文件里的段名**（`plugin.my.weather` / `[bot]` / 裸插件名都认），**空串 = 自己那段**；`key` 空串读整段、否则按点路径取键。返回 JSON 文本，找不到就是 `None` |
| `set_config(key, value_json) -> Result<(), AbiError>` | 写**自己**的段。**没有 section 参数**——宿主按执行者身份判定，写不到别人那段。`key` 空串覆盖整段 |
| `set_config_for(section, key, value_json) -> Result<(), AbiError>` | 写**指定插件**的段（跨插件同步设置）。`section` 同上；**只接受 `plugin.*`**，顶层归用户。规则与 `set_config` 一致 |

```rust
fn start(&mut self, _config_json: &str) -> Result<(), String> {
    // 读自己的段 `[plugin.demo]`（插件名点分，宿主当点路径下钻）。
    let greeting: String = self
        .host
        .get_config("demo", "greeting")
        .and_then(|json| serde_json::from_str(&json).ok())
        .unwrap_or_else(|| "hello".to_owned());
    self.host.log(LogLevel::Info, &format!("greeting = {greeting}"));

    // 读别人的段：允许（只读）。
    if let Some(city) = self.host.get_config("my.weather", "city") {
        self.host.log(LogLevel::Info, &format!("天气插件的 city = {city}"));
    }

    // 写自己的段（落盘到 plugin-config/<插件名>.toml，不碰 fuyubot.toml）。
    self.host
        .set_config("last_started", "\"2026-01-01\"")
        .map_err(|e| format!("写自己的配置失败: {e}"))?;
    Ok(())
}
```

<Callout type="info">
  `set_config` **只写你自己那一个文件**（`<项目根>/plugin-config/<插件名>.toml`，原子替换），
  不碰 `fuyubot.toml`——用户写在里面的注释、顺序、凭据都安全。三层优先级，以及「用户在
  `fuyubot.toml` 里钉住的键会拒绝写」，见[配置文件 · 插件自己的配置段](../usage/config.mdx#插件自己的配置段)。
</Callout>

## 常用 ABI 速查

`HostApi` 上的方法就是 VTable 的一对一封装（都替你处理了 `CString` 与线程局部缓冲）：

| 想干什么 | 用哪个 |
| --- | --- |
| 打日志 | `log(LogLevel, &str)` |
| 订阅 / 退订 | `on(event, Some(filter), cb, user_data)` / `off(handle)`；过滤器是 `{"字段路径": 期望值}` |
| 发自定义事件 | `emit(event, payload_json)`——只送自己 + 全局订阅者 |
| 发 TDLib 请求 | `td_invoke_simplified(method, params_json)`；响应走 `"response"` 通道（见[调用 TDLib](./tdlib.mdx)） |
| 同步执行不碰网络的方法 | `td_execute(request_json)` |
| 工具 | `register_tool(descriptor, handler, user_data)` / `register_tool_meta` / `call_tool` / `call_tool_result` / `list_tools` |
| 服务 | `provide_service`（自己作用域）/ `provide_service_shared`（进程级）/ `get_service` / `call_service`，见[插件联动](./linkage.mdx) |
| 中间件 | `use_middleware(Stage::InPlugin, cb, user_data)`，见[工具与中间件](./tools.mdx) |
| 等一条更新 | `wait_for_update(filter_json, timeout_ms)`（阻塞）或 `ResponseRouter`（可 await），见[异步等待](./async.mdx) |
| 看别人 | `list_tools()` / `list_plugins()` |
| simplify 操作表 | `simplify_invoke(op_json)` / `simplify_invoke_result(op_json)`，见 [ABI › simplify 操作表](./abi.mdx#simplify-操作表) |

## 注册一个带处理器的工具

```rust
use std::cell::RefCell;
use std::ffi::{CStr, CString};

thread_local! {
    static REPLY: RefCell<CString> = RefCell::new(CString::default());
}

unsafe extern "C-unwind" fn on_echo(
    _user: *mut std::ffi::c_void,
    input: *const std::ffi::c_char,
) -> *const std::ffi::c_char {
    // SAFETY: 宿主传的是临时 NUL 结尾字符串。
    let input = unsafe { CStr::from_ptr(input) }.to_string_lossy();
    let out = format!(r#"{{"echo":{input}}}"#);
    // 返回值必须活到宿主读完：线程局部的 CString 正好满足。
    REPLY.with(|slot| {
        *slot.borrow_mut() = CString::new(out).unwrap_or_default();
        slot.borrow().as_ptr()
    })
}

fn start(&mut self, _config_json: &str) -> Result<(), String> {
    let tool = self.host.register_tool(
        r#"{"name":"demo.echo","description":"回显入参","input_schema":{"type":"object"}}"#,
        Some(on_echo),
        std::ptr::null_mut(),
    );
    if !tool.is_valid() {
        return Err("注册工具失败".to_owned());
    }
    Ok(())
}
```

只想登记声明、不要处理器，就用 `register_tool_meta(descriptor_json)`。

## 编译与安装

```bash
cargo build --release
fuyubot plugin install target/release/fuyubot_demo.dll
```

<Callout type="error">
  `define_plugin!` **一个 crate 只能展开一次**。一个 cdylib 就是一个插件——这不是限制，是设计：
  七个导出符号名由 ABI 定死，展开两次就是重复定义。
</Callout>

要发消息、调 TDLib、等响应，见 [调用 TDLib](./tdlib.mdx)；要按字段过滤更新，见
[订阅与事件](./events.mdx)；契约本身见 [ABI 契约](./abi.mdx)。
