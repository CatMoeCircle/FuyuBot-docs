Python 插件就是一个目录：`pyproject.toml` 写身份，`main.py` 写逻辑，`fuyubot.py`（单文件薄 SDK）
管通信。上手三步见 [脚本插件](./scripts.mdx)。本页是**方法手册 + 示例**。

<Callout type="info">
  本页的 `fuyubot.py`（`fuyubot-python-host`）和 `script_plugin!` 内嵌的
  `fuyubot_plugin.py` 都支持 `run_async` / `invoke_async` / `wait_async`，
  见 [异步等待](./async.mdx)。
</Callout>

```text
my-plugin/
  pyproject.toml   ← 身份（[tool.fuyubot]：name / entry）
  main.py          ← 你写的逻辑
  fuyubot.py       ← 薄 SDK（单文件，拷进来就行）
  fuyubot.pyi      ← 类型声明（可选，IDE 补全）
```

manifest 长这样（`entry` 不写就默认 `main.py`）：

```toml
[project]
name = "my-plugin"
version = "0.1.0"

[tool.fuyubot]
name = "mybot.my-plugin"
entry = "main.py"
```

## 方法一览

薄 SDK 把 VTable 那 22 个函数包成了这些（`run()` 之前只能调同步的那几个）：

| 方法 | 走的 ABI | 干什么 |
| --- | --- | --- |
| `on(event, handler, filter=None)` | `on` | 订阅事件：事件来了就调你的函数 |
| `off(event, handler)` | `off` | 退订一个订阅（脚本订阅也能按事件 + 处理器退） |
| `invoke(method, params=None, on_response=None)` | `td_invoke_simplified` | 调一次 TDLib 接口；给了 `on_response` 就在响应回来时回调（按 `request_id` 配对，你不用记请求号） |
| `invoke_async(method, params=None)` | `td_invoke_simplified` | 同上，但返回可 `await` 的 future（**只能**在 `run_async` 里用） |
| `emit(event, payload=None)` | `emit` | 发一条自定义事件（自己 + 全局订阅者收到） |
| `log(message, level="info")` | `log` | 打日志（`debug` / `info` / `warn` / `error`） |
| `register_tool(name, description="", input_schema=None)` | `register_tool`（`meta` 版） | 登记工具**元数据**——脚本不能交函数指针，所以没有处理器 |
| `call_tool(name, input=None, on_response=None)` | `call_tool_result` | 调用一个工具，**同步**拿输出（失败是 `{"error": …}`） |
| `list_tools(on_tools=None)` | `list_tools` | 同步列出全部工具的元数据 |
| `td_execute(request, on_result=None)` | `td_execute` | **同步**执行不碰网络的 TDLib 方法（`parseTextEntities` 之类），发消息**不能**走它 |
| `use_middleware(stage, handler)` | `use_middleware` | 挂中间件（`stage` 是 0..5）；无法单独注销，随插件停止一起撤 |
| `wait_for_update(filter, timeout_ms=0, on_match=None)` | `wait_for_update` | 阻塞等一条匹配的更新（在宿主侧独立线程里等），超时 `None` |
| `wait_async(filter, timeout_ms=0)` | `wait_for_update` | 上一条的 `await` 版（**只能**在 `run_async` 里用） |
| `get_service(name, on_service=None)` | `get_service` | 读一个服务的元数据；不存在时回调收到 `None` |
| `call_service(name, method, input=None, on_result=None)` | `get_service` | 同步调用服务的某个方法 |
| `config()` | — | `plugin_start` 传进来的那份配置 JSON |
| `plugin_config()` | — | **同步**读**自己**那一段配置（`[plugin.<插件名>]`）；`run()` 之前也能用 |
| `get_config(section, key="", on_config=None)` | `get_config` | 读**任意**插件段（异步，回调在 `run()` 之后） |
| `set_config(key, value, on_done=None)` | `set_config` | 写**自己**那一段配置（成功后回写 `fuyubot.toml`） |
| `simplify_invoke(op, on_response=None)` | `simplify_invoke` | 让宿主跑一个 simplify 操作（发消息等结局、超时撤回、Markdown→entities…）；结果经 `response` 通道回投，整条 `simplifyResult` 交 `on_response`（不传就只发不收） |
| `simplify_invoke_async(op)` | `simplify_invoke` | 上一条的 future 版，`resolve` 整条 `simplifyResult`（`{ok, op, result|error}`），自己判 `ok`（**只能**在 `run_async` 里用） |
| `simplify_invoke_result(op, on_result=None)` | `simplify_invoke_result` | **同步**跑不碰网络的 op（`parse_text_entities` / `rich_from_markdown` / `list_ops`），回调收结果；传异步 op 拿到 `ok:False` / `code:"async_op"` |
| `run()` | — | 握手并开始收事件——**永远是最后一行** |
| `run_async(main=None)` | — | 同上，但跑 asyncio 事件循环，`invoke_async` / `wait_async` 要用它 |

## 一次看全：常用 ABI 怎么调

```python
import fuyubot_plugin as host


def on_ping(payload):
    chat_id = payload["message"]["chat_id"]

    # ① 发 TDLib 请求：响应按 request_id 配好对再回调，不用自己记请求号
    host.invoke("sendMessage", {
        "chat_id": chat_id,
        "input_message_content": {
            "@type": "inputMessageText",
            "text": {"@type": "formattedText", "text": "pong", "entities": []},
        },
    }, lambda resp: host.log(f"发出去了：{resp}"))

    # ② 同步执行不碰网络的方法：当场拿结果，发消息不能走它
    host.td_execute({
        "@type": "parseTextEntities",
        "text": "*粗体*",
        "parse_mode": {"@type": "textParseModeMarkdown", "version": 2},
    }, lambda result: host.log(f"解析结果：{result}"))

    # ③ 调别人的工具 / 看有哪些工具
    host.call_tool("weather.now", {"city": "上海"}, lambda out: host.log(f"天气：{out}"))
    host.list_tools(lambda tools: host.log(f"共 {len(tools or [])} 个工具"))

    # ④ 发自定义事件：自己 + 全局订阅者收得到
    host.emit("ping.seen", {"chat_id": chat_id})

    # ⑤ 等下一条更新（宿主侧独立线程里等，不卡脚本）
    host.wait_for_update({"message.content.text.text": "/pong"}, 5000,
                         lambda p: host.log("等到下一条" if p else "超时"))

    # ⑥ 读写配置：读别人的异步，写自己的会回写 fuyubot.toml
    host.get_config("my.weather", "city", lambda v: host.log(f"天气插件 city={v}"))
    host.set_config("last_seen", chat_id, lambda ok: host.log(f"写入成功={ok}"))


host.on("updateNewMessage", on_ping, {"message.content.text.text": "/ping"})
host.run()
```

三条容易踩的：

- `on_response` / `on_result` 这类回调**只在 `run()` 之后才有**——宿主得先握手；模块顶层只能调
  `plugin_config()` 这种同步的。
- `td_execute` 只给不碰网络的方法用，拿它发消息会失败。
- `wait_for_update` 是在**宿主侧**线程里等的，脚本这边不阻塞；`timeout_ms=0` 表示只检查当前状态。

## 读 / 写配置

`fuyubot.toml` 里每个插件有自己的段（见[配置文件](../usage/config.mdx)）。读**自己**那段
用 `plugin_config()`——它是**同步**的，宿主在启动脚本时就把这段塞进了 `argv[2]`，所以
`run()` 之前（模块顶层）就能用：

```python
import fuyubot_plugin as host

cfg = host.plugin_config()              # {"city": "上海"}；没配就是 {}
city = cfg.get("city", "北京")

@host.on("updateNewMessage")
def on_message(payload):
    host.log(f"城市 = {city}")
    host.get_config("my.weather", "city", lambda value: host.log(f"天气插件的城市：{value}"))

host.run()
```

```toml
# fuyubot.toml —— 这个段就叫 [plugin.<你的插件名>]
[plugin.fuyubot.python.weather]
city = "上海"
```

- **读别人的段**（`get_config`）是**异步**的：回执要等 `run()` 之后才有，所以只能在事件/中间件
  回调里用。段或键不存在时回调收到 `None`。
- **写自己的段**（`set_config`）也是异步的，成功后 `on_done(True)`，宿主会**回写
  `fuyubot.toml`**。⚠️ 回写是**全量重写**，你手写的注释会丢。
- 写失败（越权 / 值不是合法 JSON / 写盘失败）时宿主只发一条 error 日志、**不会**调 `on_done`
  ——别把「没收到回调」当成成功。

<Callout type="info">
  脚本插件只能写**自己**的段：`set_config` 没有 section 参数，宿主按调用者身份判定归属，
  所以改不到别的插件那一段（会被拒）。这是 ABI 层面的硬约束，不是薄 SDK 的限制。
</Callout>

## 事件怎么触发

你的函数只有**被事件触发**才会跑。事件有两个来源：

1. **TDLib 更新**：来一条消息、消息发送成功……每种更新是一个事件，**事件名就是更新的 `@type`**
   （`updateNewMessage`、`updateMessageSendSucceeded` ……）。每条更新会同时发到两个通道：
   具体的 `@type` 事件，和兜底的 `"update"` 事件（订阅它可以看全部）。
2. **你自己发的事件**：`emit("job_done", …)` 发出的自定义事件（细节见
   [订阅与事件](./events.mdx)）。

## `on` — 订阅事件

```python
on(event, handler, filter=None)
```

| 参数 | 说明 |
| --- | --- |
| `event` | 事件名：更新的 `@type`、`"update"`（全部更新）或你自定义的名字 |
| `handler` | 回调函数，收到一个 `payload`（解析好的 `dict`，直接取字段） |
| `filter` | 可选。只收负载里**指定字段等于指定值**的事件（点分路径写法，见下） |

**是两参数函数，不是装饰器**——`@on(...)` 会报错，老老实实 `on(事件, 函数)`。
同一个事件可以订阅多次，各带各的过滤器。

```python
from fuyubot import on, log, run

def on_message(update):
    log(f"新消息 {update['message']['id']}")

on("updateNewMessage", on_message)          # 全收
on("update", lambda u: log("来了一条更新"))   # 兜底通道
run()
```

**过滤器**：`{"点分路径": 期望值}`，负载里那个字段**等于**期望值才触发：

```python
# 只听某个群的消息
on("updateNewMessage", on_message, {"message.chat_id": -1001234567890})

# 只听 /hello 命令（文本内容匹配）
on("updateNewMessage", on_hello, {"message.content.text.text": "/hello"})
```

## `invoke` — 调 TDLib 接口

```python
invoke(method, params=None, on_response=None)
```

发一个 TDLib 请求。方法名与参数名**以 TDLib 为准**（不是 Bot API），查法见
[调用 TDLib](./tdlib.mdx)。给了 `on_response` 时回调按 `request_id` **自动配对**，
不用自己记请求号。

```python
from fuyubot import invoke

def on_message(update):
    # 发一条文本消息（TDLib 的 sendMessage + inputMessageText）
    invoke("sendMessage", {
        "chat_id": update["message"]["chat_id"],
        "input_message_content": {
            "@type": "inputMessageText",
            "text": {"@type": "formattedText", "text": "收到"},
        },
    })

# 要看结果就传第三个参数：响应回来自动调它
invoke("getMe", {}, lambda resp: print("我是", resp))
```

<Callout type="warn">
  `invoke` **不阻塞**、立即返回。响应回来时你的 `on_response` 被调用。
  不传 `on_response` 就是「发完不管」。
</Callout>

## `emit` — 发自定义事件

```python
emit(event, payload=None)
```

给**自己 + 全局订阅者**发一条自定义事件（不是广播给所有插件，见 [订阅与事件](./events.mdx)）。
适合在自己内部做「任务完成」之类的信号：

```python
on("job_done", lambda p: log(f"任务完成：{p}"))
emit("job_done", {"ok": True})
```

## `log` — 打日志

```python
log(message, level="info")
```

`level`：`error` / `warn` / `info` / `debug` / `trace`。排查问题时把配置里
`[plugins].log_level` 调成 `"debug"`（见[配置文件](../usage/config.mdx)）。

```python
log("普通信息")
log("要坏事了", "warn")
```

## `register_tool` — 登记工具

```python
register_tool(name, description="", input_schema=None)
```

只登记**元数据**（名字、说明、参数的 JSON Schema），让宿主知道有这个工具；
调用分发看 [工具与中间件](./tools.mdx)。

```python
register_tool("weather", "查天气", {
    "type": "object",
    "properties": {"city": {"type": "string"}},
    "required": ["city"],
})
```

## `use_middleware` — 挂中间件

```python
use_middleware(stage, handler)
```

`handler(stage, payload)` 在更新流经管线时被调用，可以检查或改写负载。
`stage` 是阶段号；细节看 [工具与中间件](./tools.mdx)。

```python
def audit(stage, payload):
    log(f"阶段 {stage} 看到一条更新")

use_middleware(2, audit)
```

## `run` — 启动

```python
run()
```

发就绪握手、开始收事件，**阻塞到进程结束**。**必须是最后一行**——它提前返回 = 插件加载失败。

## 完整示例

**Echo 机器人**——回声复读：

```python
from fuyubot import on, invoke, log, run

def echo(update):
    message = update.get("message") or {}
    content = message.get("content") or {}
    text = (content.get("text") or {}).get("text", "")
    if not text or message.get("is_outgoing"):
        return   # 别回自己发的，否则自激
    invoke("sendMessage", {
        "chat_id": message["chat_id"],
        "input_message_content": {
            "@type": "inputMessageText",
            "text": {"@type": "formattedText", "text": text},
        },
    })

on("updateNewMessage", echo)
run()
```

**命令处理器**——不同命令各干各的：

```python
from fuyubot import on, invoke, run

def reply(chat_id, text):
    invoke("sendMessage", {
        "chat_id": chat_id,
        "input_message_content": {
            "@type": "inputMessageText",
            "text": {"@type": "formattedText", "text": text},
        },
    })

def on_hello(update):
    reply(update["message"]["chat_id"], "你好！")

def on_ping(update):
    reply(update["message"]["chat_id"], "pong")

on("updateNewMessage", on_hello, {"message.content.text.text": "/hello"})
on("updateNewMessage", on_ping,  {"message.content.text.text": "/ping"})
run()
```

**看全部流量**——兜底通道记日志：

```python
from fuyubot import on, log, run

on("update", lambda u: log(f"更新：{u.get('@type')}"))
run()
```

## 发消息：手写 `sendMessage`（或者用 `simplify_invoke`）

> ✅ **ABI v5 起，这一节只是「另一条路」，不再是唯一的路。** 宿主从 v5 开始自己跑
> 同一份 `fuyubot-simplify` 代码，经 `simplify_invoke` / `simplify_invoke_result` 暴露成一张
> **op 表**（`{"op":"send_message","args":{…}}`），所有语言都能用——发消息等结局、超时撤回、
> bot 与用户号挑不同反应方法、Markdown → entities、富消息本地块树，都不用手写。
> 见 [ABI › simplify 操作表](./abi.mdx#simplify-操作表)。
> ✅ Python 薄封装已经支持 `simplify_invoke` / `simplify_invoke_async` / `simplify_invoke_result`
> （见上表）——直接调用即可，不必手写下面这些字段。


先来一个能跑的：用 `simplify_invoke` 发消息——宿主替你把文本解析成 `formattedText`、
等到「真发出去」那条 `Message`、超时还会先撤回（结果经 `response` 通道回投）：

```python
import fuyubot_plugin as host


def on_send_result(result):
    # result 形状: {"@type":"simplifyResult","op":"send_message","ok":bool,"result"|"error":{...}}
    if result.get("ok"):
        msg = result["result"]
        host.log(f"已发出，最终消息 id={msg.get('id', '?')}")
    else:
        err = result["error"]
        host.log(f"发送失败：{err['code']} {err['message']}", "error")


# 在事件回调里调用（回投通道在 run() 之后才握手）
def on_new_message(update):
    host.simplify_invoke({
        "op": "send_message",
        "args": {
            "chat_id": update["message"]["chat_id"],
            "input_message_content": {
                "@type": "inputMessageText",
                # 纯字符串即可，simplify 按纯文本处理；
                # 想要 Markdown/HTML 就写 {"text": ..., "parse_mode": "markdown"|"markdown_v2"|"html"}
                "text": "你好，这是用 simplify 发的",
            },
            "timeout_ms": 30000,
        },
    }, on_send_result)


host.on("updateNewMessage", on_new_message)
run()
```

只想要同步拿结果（不碰网络的 op）就用 `simplify_invoke_result`，回调里收整条 `simplifyResult`：
`parse_text_entities` / `rich_from_markdown` / `list_ops`。传需要等 TDLib 应答的异步 op
会拿到 `ok:False` / `code:"async_op"`。

手写 `sendMessage` 是**另一条路**——下面这些字段你都得自己拼对：

| 想要的效果 | 手写的关键字段 |
| --- | --- |
| 纯文本 | `input_message_content` = `inputMessageText`，里面 `text` 是 `formattedText`（`text` + `entities`） |
| Markdown / HTML | **不自己解析**：先 `td_execute` 调 `parseTextEntities`（`version: 2` = MarkdownV2，`textParseModeHTML` = HTML），把返回的 `formattedText` 整个塞进去 |
| 回复某条 | `reply_to` = `{"@type": "inputMessageReplyToMessage", "message_id": N}` |
| 发到话题 | `topic_id` = `{"@type": "messageTopicForum", "forum_topic_id": N}`（论坛）；非论坛的评论串才是 `messageTopicThread` |
| 内联按钮 | `reply_markup` = `replyMarkupInlineKeyboard`；⚠️ callback 按钮的 `data` 是 **base64**（TDLib 里它是 `bytes`） |
| 静音 / 保护内容 | 都在 `options`（`messageSendOptions`）里，不是顶层字段 |
| 等到「真发出去」 | `on_response` 只到**临时消息**；要最终那条 `Message` 得再等一条 `updateMessageSendSucceeded` |

```python
import base64
import fuyubot_plugin as host


def send_markdown(chat_id, markdown, reply_to=None):
    """发一条 MarkdownV2 消息：先问 TDLib 要 entities，再发出去。"""

    def on_parsed(result):
        text = result if result else {"@type": "formattedText", "text": markdown, "entities": []}
        body = {
            "chat_id": chat_id,
            "input_message_content": {"@type": "inputMessageText", "text": text},
        }
        if reply_to:
            body["reply_to"] = {"@type": "inputMessageReplyToMessage", "message_id": reply_to}
        host.invoke("sendMessage", body, lambda resp: host.log(f"已发：{resp}"))

    host.td_execute({
        "@type": "parseTextEntities",
        "text": markdown,
        "parse_mode": {"@type": "textParseModeMarkdown", "version": 2},
    }, on_parsed)


def send_with_button(chat_id, label, payload):
    """带一个回调按钮；data 在 TDLib 里是 bytes，JSON 里要写 base64。"""
    host.invoke("sendMessage", {
        "chat_id": chat_id,
        "input_message_content": {
            "@type": "inputMessageText",
            "text": {"@type": "formattedText", "text": label, "entities": []},
        },
        "reply_markup": {
            "@type": "replyMarkupInlineKeyboard",
            "rows": [[{
                "@type": "inlineKeyboardButton",
                "text": "确认",
                "type": {"@type": "inlineKeyboardButtonTypeCallback",
                         "data": base64.b64encode(payload.encode()).decode()},
            }]],
        },
    })
```

方法名拿不准就问 SDK，它读的是真 `td_api.tl`：`fuyubot-sdk td-method sendMessage`。

## 常见问题

- **原生桥**：薄 SDK 要加载原生桥（和托管插件同一份库）。查找顺序：脚本同目录 →
  环境变量 `FUYUBOT_NATIVE_LIB` → 当前工作目录。找不到会报
  「找不到 fuyubot 原生桥库」，排法见 [脚本插件常见问题](./scripts.mdx#常见问题)。
- **自检**：`python fuyubot.py` 验证 API 形状（不碰宿主），输出 `fuyubot: self-test ok`。
- **依赖工具**：要装 [uv](https://docs.astral.sh/uv/)（机器人用 `uv sync` 装依赖、`uv run` 起脚本）。
- **payload 取字段**：先判空再取（`dict.get()`），不同更新类型的字段位置不一样；
  `updateNewMessage` 的文本在 `message.content.text.text`。
