`fuyubot-simplify` 只做一件事：**把 TDLib 的输入拼好、把结果等回来**，返回值仍然是 TDLib 的原始 JSON
（`Value` / `Vec<Value>`）。

```rust
let simplify = Simplify::new(host); // HostApi 是 Copy，随手复制
```

三条贯穿全部方法的约定：

1. **每个方法都等到结果才返回**，不交回请求号；唯一的例外是 `formatted`（同步调用，压根没有等待）。
2. **等待的方法是阻塞的**。插件的更新回调就跑在 TDLib 接收循环那个线程上，在那里等待=自己卡自己，
   等到的一定是超时。回调里一律用 `*_then`（见第 13 节）。
3. 失败一律是 `Err(SimplifyError)`，成功时的返回值见第 14 节。

本文按**功能范围**分组；想知道这些方法内部怎么实现（为什么这么拼、为什么这么等），
看[开发 › simplify 封装是怎么实现的](../dev/simplify-internals.mdx)。

除了发/改/删，这一层还收了四件「TDLib 里没有直觉上那个方法」的事：
[管理权](#11-管理权adminright) / [转发](#12-转发forwardparams) /
[表情反应](#13-表情反应reaction) / [连接状态](#14-连接状态connectiontracker)。

## 1. 文本内容：`Text` 与 `ParseMode`

带标记的文本**不由本 crate 解析**——经**同步**的 `td_execute` 问 TDLib 的 `parseTextEntities`
（为什么不能用异步，见[开发 › simplify 封装是怎么实现的](../dev/simplify-internals.mdx)里的「文本链路」一节）。

<TypeTable
  type={{

      type: 'String',
      required: true,
    },
    parse_mode: {
      description: '怎么解析它；Plain = 原文照发。',
      type: 'ParseMode',

    },
  }}
/>

快捷构造：`Text::plain` / `Text::markdown` / `Text::markdown_v2` / `Text::html` / `Text::new(text, mode)`；
`&str` / `String` 直接转成纯文本。

| `ParseMode` | 发出的 `parse_mode` |
| --- | --- |
| `Plain`（默认） | **不发请求**，直接 `formattedText { text, entities: [] }` |
| `Markdown` | `textParseModeMarkdown` + `version: 1` |
| `MarkdownV2` | `textParseModeMarkdown` + `version: 2` |
| `Html` | `textParseModeHTML` |

⚠️ **真库实测（TDLib 1.8.68，1.8.66 同结论）：MarkdownV2 的粗体是 `*x*`，不是 `**x**`。**
`**bold**` 会被吞成 `bold` 而且**不给** bold entity，`__x__` 出来的是下划线。别按 CommonMark 的直觉写
——这正是「不自己实现解析」的理由。

拿到结果也没干活不符预期：**拿不到就退回纯文本**并打一条 `Warn` 日志（没接 TDLib、TDLib 报错都一样），
一条 Markdown 写错的消息不该整条发不出去。

### 话题：`Topic`

`topic_id` 不是裸 id，是 TDLib 的 `MessageTopic`——**四个构造器各有各的 id 类型**，选错了 TDLib 就拒：

| 构造 | 用在哪 | 发出的 `topic_id` |
| --- | --- | --- |
| `Topic::forum(id)` | **论坛**群组，以及与 bot 的私聊 | `{"@type":"messageTopicForum","forum_topic_id":…}` |
| `Topic::thread(id)` | **非论坛**群组的评论串 | `{"@type":"messageTopicThread","message_thread_id":…}` |
| `Topic::direct_messages(id)` | 频道的私信话题 | `{"@type":"messageTopicDirectMessages","direct_messages_chat_topic_id":…}` |
| `Topic::saved_messages(id)` | 收藏夹话题 | `{"@type":"messageTopicSavedMessages","saved_messages_topic_id":…}` |

⚠️ 刻意**没有** `From<i64>`：论坛话题是 `int32`、评论串是 `int53`，一个裸数字说不清是哪一种，
隐式转任何一个都会在另一种群里静默发错。（这一层以前固定按 `messageTopicThread` 拼，非论坛群以外全是错的。）

## 3. 媒体：`Media` / `InputFile` / `Thumbnail`

七个变体对应 TDLib 的七个 `inputMessage*` 构造器：

| 变体 | 内容类型 | 能设置的字段 |
| --- | --- | --- |
| `Media::photo(file)` | `inputMessagePhoto` | `caption` / `thumbnail` / `width` / `height` / `has_spoiler` |

| `Media::location(lat, lng)` | `inputMessageLocation` | — |

链式设置器都返回新的 `Media`，**只在真签名里有那个字段的变体上生效**（其余原样返回）：

| 设置器 | 作用范围 | 字段 |
| --- | --- | --- |
| `.caption(text)` | 图 / 视频 / 音频 / 文档 / 动图 | `caption` |
| `.thumbnail(thumb)` | 上述五个 + 贴纸 | `thumbnail`（音频那个真名是 `album_cover_thumbnail`） |
| `.cover(file, 秒)` | 视频 | `cover` + `start_timestamp` |
| `.spoiler(bool)` | 图 / 视频 / 动图 | `has_spoiler`（发过去先遮住，点一下才显示） |
| `.size(w, h)` | 图 / 视频 / 动图 / 贴纸 | `width` / `height`（填 0 = TDLib 自己读） |
| `.duration(秒)` | 视频 / 音频 / 动图 | `duration` |
| `.streaming(bool)` | 视频 | `supports_streaming` |
| `.title(..)` / `.performer(..)` | 音频 | `title` / `performer` |
| `.emoji(..)` | 贴纸 | `emoji` |

```rust
Media::video("/tmp/a.mp4")
    .caption(Text::plain("视频"))
    .thumbnail(Thumbnail::new("/tmp/thumb.jpg").size(320, 240))
    .cover("/tmp/cover.jpg", 3) // 封面帧 + 从第 3 秒开始播
    .size(640, 480)
    .duration(3)
    .streaming(true)
    .spoiler(true)
```

没设置的字段**整个不发**（不是发 `null`）。⚠️ 真库：`cover` **不支持**秘密聊天与阅后即焚消息。

## 11. 管理权：`AdminRight`

判定规则（[`is_admin_status`](#11-管理权adminright)）：

| `status.@type` | `right: None` | `right: Some(x)` |
| --- | --- | --- |
| `chatMemberStatusCreator`（群主） | `true` | `true`——群主拥有一切（唯一例外见下） |
| `chatMemberStatusAdministrator` | `true` | `status.rights.<x>` 必须为 `true`，字段缺失按 `false` |

⚠️ 群主的**匿名**是 `status.is_anonymous`，不在 `rights` 里——所以 `Some(AdminRight::IsAnonymous)`
对群主读的是前者。`AdminRight` 共 18 项，名字就是 `chatAdministratorRights` 的字段名
（`can_manage_chat` / `can_delete_messages` / `can_pin_messages` / …），认不出的字段名
`AdminRight::from_key` 返回 `None`。

拿不到成员信息（超时 / TDLib 报错 / 不是群聊）一律 `false`：**不确定时说「没有」比说「有」安全**。

/>

走的是 `forwardMessages`（一次一组，**不是** Bot API 的 `forwardMessage`）。返回的是**还没发完**的临时消息
——这里只等**响应**，不等发送结局，最终消息照旧经 `updateMessageSendSucceeded` / `updateMessageSendFailed`
回来。单项没转发成功时 TDLib 在对应位置放 `null`，所以数组长度与排序后的 `message_ids` 一致、
但元素可能是 `Null`。

空列表 → `SimplifyError::EmptyForward`，超过 100 条 → `TooManyForward`，两者都在发请求**之前**挡掉。

## 13. 表情反应：`Reaction`

bot 与用户号**不是同一个方法**，这一点没有「通用写法」可言：

| 方法 | 用哪个 TDLib 方法 | 语义 |
| --- | --- | --- |
| `react(chat_id, msg, &reaction, is_big, timeout_ms)` | **自动**：bot → `setMessageReactions`，用户 → `addMessageReaction` | 加一个反应 |
| `unreact(chat_id, msg, &reaction, timeout_ms)` | **自动**：bot → `setMessageReactions` 传空列表，用户 → `removeMessageReaction` | 去掉反应 |
| `add_reaction(..)` | 固定 `addMessageReaction` | 已知自己是用户号时省掉 `getMe` |
| `set_reactions(..)` | 固定 `setMessageReactions` | 已知自己是 bot 时；空切片 = 清空 |

自动判定靠 `getMe` 的 `user.type.@type == "userTypeBot"`，也就是说 `react` / `unreact` 每次会多一次
`getMe` 往返（它不碰服务器，TDLib 本地应答）。⚠️ bot 侧没有「删一个」的说法，只能整组覆盖——
所以 **bot 的 `unreact` 会忽略 `reaction` 参数**，直接清空。

`Reaction::emoji("👍")` → `reactionTypeEmoji`；`Reaction::custom_emoji(id)` → `reactionTypeCustomEmoji`。
付费反应（`reactionTypePaid`）不在这套里。

## 14. 连接状态：`ConnectionTracker`

TDLib **没有** `getConnectionState`——连接状态只以 `updateConnectionState` 的形式出现，
所以「现在连上了吗」只能自己订阅并记住最新那条。

两个坑：

- **订阅之前推过的更新补不回来**（TDLib 的状态更新不重放），所以在插件 `start` 里尽早调；
  晚订阅只会漏掉开头的 `Connecting` / `Updating`。
- 这是**连接**状态（到 Telegram 的链路），**不是**授权状态（`updateAuthorizationState`，登录那一套）。

```rust
// 之后
if self.connection.as_ref().is_some_and(|c| c.is_ready()) { /* … */ }
```

## 15. 不挂在 `Simplify` 上的公开函数

纯函数，随手支配——想绕过某些方法的等待语义、自己拼请求时尤其有用：

| 函数 | 作用 |
| --- | --- |
| `send_params` / `album_params` / `edit_text_params` / `edit_caption_params` / `edit_media_params` / `edit_markup_params` | 组装参数（**不含 `@type`**，那是宿主补的） |
| `chat_member_params(chat_id, user_id)` / `forward_params(chat_id, from_chat_id, &params)` | 管理权 / 转发的参数（含 `MessageTopic` 与 `MessageSender` 的嵌套形状） |
| `reaction_params` / `set_reactions_params` / `remove_reaction_params` | 三种反应请求的参数（user 分支与 bot 分支分开） |
| `is_admin_status(&status, right)` | 判一份 `ChatMemberStatus` 有没有管理权，不发请求 |
| `content_json(&Media, render)` | 媒体 → `InputMessageContent` |
| `parse_text_request(&Text)` | `parseTextEntities` 的请求；`Plain` 返回 `None` |
| `formatted_from(&Text, Option<&Value>)` / `is_formatted_text(..)` | 响应 → `formattedText`；拿不到退回纯文本 |
| `plain_text(&Text)` | 纯文本 → `formattedText`（不花往返），也是默认渲染器 |
| `command_of(&Value)` / `on_command(host, handler)` | 见[第 7 节](#7-命令与输入) |

## 16. 参数名为什么是这几个

真 `td_api.tl`：`sendMessage chat_id topic_id reply_to options reply_markup input_message_content`
——**没有** `message_thread_id` / 顶层 `disable_notification` / 顶层 `caption`（那些是 Bot API 的名字）。
短名字到 TDLib 字段的映射只有一处实现：

| 参数结构体的字段 | 落到的 TDLib 字段 |
| --- | --- |
| `topic_id: Some(Topic::forum(n))` | `topic_id` = `{"@type":"messageTopicForum","forum_topic_id":n}` |
| `topic_id: Some(Topic::thread(n))` | `topic_id` = `{"@type":"messageTopicThread","message_thread_id":n}` |
| `reply_to_message_id` | `reply_to` = `{"@type":"inputMessageReplyToMessage","message_id":…}` |
| `reply_markup` | `reply_markup` = `{"@type":"replyMarkupInlineKeyboard","rows":…}` |
| `link_preview: Some(false)` | `inputMessageText.link_preview_options.is_disabled = true` |
| `text` / `media.caption` | `formattedText`（经 `parseTextEntities`） |
| `is_chat_admin` 的 `user_id` | `getChatMember.member_id` = `{"@type":"messageSenderUser","user_id":…}` |

## 17. 异步版：`*_then`

每个等待版都有一个 `*_then`（`send_message_then` / `send_message_album_then` /
`edit_message_text_then` / `edit_message_caption_then` / `edit_message_media_then` /
`edit_message_reply_markup_then` / `delete_message_then` / `answer_callback_query_then` /
`forward_messages_then` / `react_then` / `unreact_then`）：
把等待挪到另一个线程，**立刻返回**，结局交给闭包。

```rust
simplify.send_message_then(chat_id, &params, |result| match result {
    Ok(message) => { /* 最终消息 */ }
    Err(error) => host.log(LogLevel::Error, &format!("发送失败: {error}")),
});
```

⚠️ 它们返回那个线程的 `JoinHandle`——**插件要在 `stop()` 里 join 掉**，否则动态库卸载之后线程还在跑库里的代码。
