---
title: 离线回放
description: 不接账号验证插件
---

`fuyubot run --replay` 把一批更新的 JSON 灌进整条管线后退出：**不接 TDLib、不用账号**，用来在任何机器上验插件。

```powershell
.\fuyubot.exe run --replay examples/replay/new_message.json --plugin-dir <插件目录> --replay-wait 5000
```

```text
--replay：本次不接 TDLib（回放是离线的，请求只留档）
已加载插件 mybot (demo\plugins\mybot.dll)
fuyubot（fuyubot 0.1.0）已启动：插件 1 个，工具 0 个
回放 updateNewMessage → UpdateOutcome { update_type: "updateNewMessage", listeners: 1, warnings: [] }
插件打出来的日志：
  Info mybot: init
  Info mybot: start()
插件发出去的请求：
```

**每条 update 打一行**，`listeners` 是收到它的订阅数。退出码 0 表示回放成功，非零表示插件加载或回放本身失败。

## 输出里看什么

| 段落 | 含义 |
| --- | --- |
| `回放 <@type> → UpdateOutcome { … }` | 管线跑完一条更新的结果。`warnings` 非空说明有阶段或回调抱怨过 |
| `插件打出来的日志：` | 插件 `log` 的原样回显（`Info mybot: init` / `start()` 是插件生命周期） |
| `插件发出去的请求：` | 插件请求的**留档**。回放不连 Telegram，所以请求不会真的发出去 |

回放是离线路径，所以插件发请求只留档、也不会等响应——要验「响应回到插件」用真 TDLib，并准备好账号。

## 慢插件与脚本插件：`--replay-wait`

回放完不是立刻退出，而是等一个**安静窗口**再看结果。窗口的默认值按插件形态自动选：

| 插件形态 | 默认窗口 |
| --- | --- |
| 有脚本（`plugins/scripts/` 下有目录，或插件包里 `kind` 是 `python` / `js`） | 2000 ms |
| 纯原生（Rust / C / C++ / Go） | 150 ms |

脚本插件跑在子进程里：事件要经管道过去、反应再经管道回来，还可能捎带网络请求，
窗口太短会把它们的日志与请求整批漏掉。插件要发慢速网络请求就把它调大：

```powershell
.\fuyubot.exe run --replay examples\replay\new_message.json --plugin-dir <插件目录> --replay-wait 5000
```

## 插件目录别指 `target\debug`

`--plugin-dir` 要指向「只放你要验的插件」的目录。指 `target\debug` 会把整仓的示例产物一起加载，
任何一个起不来都会让输出混进一堆「跳过 xxx」。

正确做法是先装到一个干净目录再回放：

```bash
cargo build -p fuyubot-plugin-demo
fuyubot plugin install target/debug/fuyubot_plugin_demo.dll --plugin-dir demo-plugins
fuyubot run --replay examples/replay/new_message.json --plugin-dir demo-plugins
```

## 与实例的关系

<Callout type="info">
  `--replay` **不占单实例锁、不发布状态**：同一个目录可以一边跑着实例、一边回放。它也**不会自动 init**（回放不该因为你试了一次就在当前目录留下 `fuyubot.toml`），没有配置就按默认值跑，也不碰 `.fuyubot/` 里的实例状态。
</Callout>

- 回放**不接 TDLib**（无论有没有 `tdjson`）：这是硬约定，否则回放就要账号和网络。
- 要看运行中的实例、后台跑、优雅停止，见 [运行与实例管理](./run.mdx)。
- 回放里插件加载失败，多半是 ABI 版本或路径的问题，见 [常见问题](./troubleshooting.mdx)。
