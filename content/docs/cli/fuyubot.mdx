跑框架的那个 CLI。它就是运行时包里的 `fuyubot(.exe)`（从源码跑时是 `target/{debug,release}/fuyubot`）。

```text
fuyubot <COMMAND>

Commands:
  init    初始化一个 fuyubot 项目（生成 fuyubot.toml 与插件目录）
  run     起框架、加载插件（`--tui` 打开终端操作面板）
  login   只登录，不起框架：走完授权、session 落盘后退出
  logout  清掉本地 TDLib 会话（= 退出登录；默认只预览）
  status  看这个目录上的实例在不在跑（读 .fuyubot/）
  stop    停掉这个目录上跑着的实例
  config  看配置：打印**生效值**（默认值 + 向上找到的那份文件）
  plugin  插件管理
```

## `init`

```text
fuyubot init [--dir <DIR>] [--name <NAME>] [--api-id <API_ID>]
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--dir` | `.` | 项目目录，生成 `<dir>/fuyubot.toml` 与 `<dir>/plugins/` |
| `--name` | `fuyubot` | 只影响配置里的 `name` |
| `--api-id` | `0` | TDLib api_id（不是秘密，可以写进配置）；`0` = 没配，`run` 会问 |

`init` **只写 `api_id`**：`api_hash` 这个命令连参数都不收（init 阶段手上不该有它）——`run` 首次会问，问完写回配置。
重复 `init` 会被挡住（不覆盖你改过的配置）。

```text
$ fuyubot init --dir demo --name mybot --api-id 12345
已生成 demo\fuyubot.toml
插件目录：demo\plugins
下一步：fuyubot-sdk init demo --lang rust（插件脚手架由开发 CLI 生成）
```

## `run`

```text
fuyubot run [--config <CONFIG>] [--plugin-dir <PLUGIN_DIR>] [--api-id <ID>] [--no-tdlib]
            [--no-login] [--background] [--tui] [--replay <REPLAY>] [--replay-wait <MS>]
```

| 参数 | 作用 |
| --- | --- |
| `--config` | 配置文件，默认 `fuyubot.toml`（缺这个文件时 `run` 会按模板自动生成一份） |
| `--plugin-dir` | 覆盖 `[plugins].dir` |
| `--api-id <ID>` | 覆盖配置里的 `api_id`（**不是**秘密，可以写在命令行 / 脚本里）。优先级：`--api-id` → `TG_API_ID` → 配置 `[telegram].api_id` → 交互提问。`api_hash` 没有对应参数（只走 `TG_API_HASH` 或交互输入） |
| `--no-tdlib` | 不接 TDLib，只加载插件 |
| `--no-login` | 接 TDLib 但不走登录流程（已有 session 照样能用；CI / 容器用） |
| `--background` | 派生无终端的子进程，stdout/stderr 进 `logs/fuyubot.log`，父进程等状态发布后返回 |
| `--tui`（短写 `-t`） | 打开**终端操作面板**（顶部版本栏 + 导航/工作区 + 底部操作与资源占用），而不是前台跑 bot。面板自己不接 TDLib、不加载插件；`s` 派生 `run --background`，`x` 走优雅停止。与 `--background` / `--replay` 互斥 |
| `--replay <文件>` | 把一批更新 JSON 灌进管线后退出：**不接 TDLib、不用账号** |
| `--replay-wait <MS>` | 回放后等插件的静默窗口；不填按插件形态自选（脚本插件 2000，原生 150） |

`run` 不带 `--replay` 的顺序：自动 init → 拿单实例锁 → attach TDLib → 问/读凭据 → **加载全部插件** →
发 `setTdlibParameters` 并登录 → `getMe` 打印账户 → 发布状态 → 才开始分发。
**登录这一步没有真账号端到端验过**，要立刻验插件就用 `--replay`——想单独把登录走完（不起框架）用 `login`。

```powershell
.\fuyubot.exe run --config demo\fuyubot.toml                 # 前台，可交互登录
.\fuyubot.exe run --config demo\fuyubot.toml --background    # 日志进 demo\logs\fuyubot.log
.\fuyubot.exe run --replay ping.json --plugin-dir demo\plugins
```

后台运行**没有 stdin**：没有 session 又没有 `TG_BOT_TOKEN` 时会直接失败并把日志尾巴打出来——
先用前台登录一次（session 落在 `data/`）。

### 终端操作面板（`--tui`）

```powershell
.\fuyubot.exe run --tui --config demo\fuyubot.toml
```

布局固定为四段：**顶部版本栏**（`[fuyubot - v…]`；实例运行中才显示状态，没跑时只显示刷新时间）、
**左侧导航**（概览 / 插件 / 日志 / 配置 / 帮助）、**中央工作区**、**底部两行**
（第一行是当前可用操作，第二行是 CPU / 内存 / 运行时长 / 加载插件数 / 日志级别 / PID）。
顶部和底部**不铺背景色**，只靠边框高亮表示焦点。

> 底部的资源数字来自 `sysinfo`，采的是**运行中实例的 PID**（不是面板自己）；
> 实例没跑时 CPU / 内存 / 运行 / PID 显示 `—`、插件数为 0，日志级别显示面板下次启动会用哪一档。
> 启动后的第一个采样点 CPU 是 `0.0%`，下一秒才有真实值。

> 概览页「运行」区有三行是**从实例学来的**：TDLib 连接、TDLib 授权、账户。账户是登录后由
> `getMe` 写进 `.fuyubot/status` 的（名字 + `@用户名`，宽屏再补 `id` 与 bot / user），
> 之后 TDLib 用 `updateUser` 改名字 / 用户名时，实例把新值重发进 status，面板下一帧就跟着变。

| 按键 | 作用 |
| --- | --- |
| `Tab` / `Shift+Tab` | 在**导航**与**工作区**之间切换焦点（当前窗口边框高亮，底栏显示 `[导航]` / `[工作区]`） |
| `Enter` / `Esc` | 导航 → 工作区 / 工作区 → 导航（在导航上按 `Esc` 才退出面板） |
| `↑` / `↓`、`j` / `k` | 导航焦点：切换页面；工作区焦点：滚动日志 / 选择配置项 / 移动日志选择 |
| `←` / `→` | 切换顶部标签页（窄屏横向导航；工作区焦点也生效） |
| `h` / `l` | 导航焦点：上一页 / 下一页 |
| `1`–`5` | 直接跳到概览 / 插件 / 日志 / 配置 / 帮助 |
| `Enter` | 日志页：进入日志选择模式；配置页：编辑选中的配置项（`e` 同） |
| `y` | 日志选择模式：复制选中行（TDLib Update 复制完整 JSON） |
| `s` | 启动 bot（等价于 `fuyubot run --background`） |
| `x` → `y` | 停止 bot（`y` 是确认框里的确认；走 `.fuyubot/stop` 的优雅停止） |
| `r` | 刷新状态 / 插件 / 日志 / 配置 |
| `l` | 日志页 + 工作区焦点：调整日志级别（error / warn / info / debug / trace） |
| `F` | 日志页 + 工作区焦点：按级别 / 来源过滤日志 |
| `c` | 日志页 + 工作区焦点：清空当前日志文件（要确认） |
| `f` | 日志页 + 工作区焦点：跟随末尾开关 |
| `PgUp` / `PgDn`、`Home` / `End` | 工作区焦点：日志 / 帮助翻页、首尾；配置页选择翻页、首尾 |
| `q`、`Ctrl+C` | 退出面板（**不会**停掉已启动的实例） |

面板**不占实例锁、不加载插件、不接 TDLib**：同一个 TDLib 数据目录同一时刻只能一个进程打开，
所以它只读 `.fuyubot/status`、配置、插件目录和 `logs/fuyubot.log`。启停都派生子进程，
和手敲命令走同一条路——面板里看到的就是真正在跑的那个实例。

日志页按 `l` 打开级别选择框：写入 `.fuyubot/log-level`，运行中的实例每 500ms 读一次并切换，
`status` 随后显示新的 `log_level`。这是**运行期**开关：只对本次运行生效，重启回到
`[plugins].log_level`（新实例拿锁时会清掉控制文件）。

`F` 打开过滤弹框：`↑↓` 选「级别 / 来源」，`←→` 改值，`c` 重置，`Enter` 应用。
级别是下限（`info+` = error / warn / info）；来源分插件 / 宿主 / 管道 / 更新 / TDLib / 其他。
新日志格式按「插件行 / source 词」归类（旧四列也兼容）：`TDLib Update` 追踪归**更新**（级别 trace），
TDLib C 库的 `[ N][t …]` 原样行归 **TDLib**；认不出级别的启动提示按 info 对待。
日志页底栏会显示 `x/y 行`。日志字段不按固定列补空格，长行会按**显示宽度**折行
（续行缩进两格），不会直接截掉后半段。

TDLib Update 行在 TUI 里**只显示 `@type`**（例如 `TDLib Update  updateNewMessage`），
不再把整段 JSON 铺在屏幕上。按 `Enter` 进入选择模式：`↑↓` 选行，`y` 或 `Enter`
把选中行复制到系统剪贴板；TDLib Update 复制的是**完整 JSON**（不含时间戳等前缀），
其它行复制整行。`Esc` 退出选择模式。

每次新启动后台实例都会先截断 `logs/fuyubot.log`（旧日志不保留）；日志页按 `c`
可以手动清空当前日志文件，确认后清空并回到跟随末尾，运行中的实例会继续写新行。

窄终端（手机 / Termux）会自适应：宽度不足 90 列时左侧导航收窄，低于 60 列时导航
移到工作区上方、变成一行横向标签，用 `←` / `→`（工作区焦点也生效）或 `h` / `l`
（导航焦点）切换；更窄时标签退化成单字。底栏资源在窄屏只留 `CPU / 内存 / 级别`，
不显示运行时长、插件数量和 PID；配置项在窄屏改成「完整键 + 值」两行；帮助页可用
`↑↓` / `PgUp` / `PgDn` 滚动；概览里的绝对路径改成相对项目根的路径。日志在窄屏只留
`HH:MM:SS`、插件名最后一段和级别，消息照常折行。复制优先用
`termux-clipboard-set`（需装 `termux-api`），否则退回 OSC 52。

配置页是**可编辑的表格**（段 / 键 / 生效值 / 来源），`↑↓` 选中、`Enter` 或 `e` 编辑。
文本、整数（带上下界）和枚举（`account_type` / `log_level`）会先校验再写回；写回是
**单行文本替换**，保留文件里的注释、顺序和 CRLF，键/段不存在就补。运行中保存的配置
**重启后生效**；`api_hash`、Bot Token / 手机号 / 密码和 `[plugin.*]` 段只读（插件段请用
插件自己的命令或直接编辑文件）。配置文件读不出来时配置页会显示错误原文，改好按 `r` 重读。

## `login`

```text
fuyubot login [--config <CONFIG>] [--api-id <ID>]
```

**只登录，不起框架**：建 TDLib 客户端 → 走完授权 → 打印账户 → 退出。**不加载插件、不开接收循环**。
session 落在 `data/`，之后 `fuyubot run`（含 `--background`）起来就直接进 `Ready`——后台跑没有 stdin、
登录问不了，先前台 `login` 一次正是给这条路准备的。

| 参数 | 作用 |
| --- | --- |
| `--config` | 配置文件，默认 `fuyubot.toml`（缺文件时同样会自动生成一份） |
| `--api-id <ID>` | 与 `run` 的 `--api-id` 同义、同优先级（`--api-id` → `TG_API_ID` → 配置 → 提问） |

凭据解析、授权状态机、账户打印全部复用 `run` 的那套，两条路不会漂移。两条额外限制：

- **实例在跑时拒绝**：TDLib 的 sqlite + binlog 同一时刻只能一个进程打开，`login` 再开一次会把跑着的实例拆坏。
- **TDLib 没就绪就报错退出**，告诉你缺什么（`TDLIB_TDJSON_PATH` / exe 同级 tdjson / `[tdlib].path`）。

```text
$ fuyubot login --config demo\fuyubot.toml
只登录：不加载插件、不开接收循环；登完就退出（之后 `fuyubot run` 会直接用这份 session）
…授权过程…
登录完成：session 在 demo\data——`fuyubot run`（含 `--background`）起来会直接进 Ready
```

## `logout`

```text
fuyubot logout [--config <CONFIG>] [--yes]
```

清掉本地 TDLib 会话目录（= `[telegram].data_dir`，默认 `<项目根>/data`，里面是数据库与 binlog）＝ 退出登录，
下次要重新登录。**默认只打印将要删除什么**，加 `--yes` 才真删。

它**只清本地**：不发服务端的 `logOut`（Telegram 那边的会话还在，只是本机这份没了）。

| 参数 | 作用 |
| --- | --- |
| `--yes` | 真的删除。不加就是预览，一个文件都不动 |

三道守卫与 `--yes` 无关，命中就拒绝：

| 守卫 | 行为 |
| --- | --- |
| 实例在跑 | 拒绝（预览前、真删前各挡一次）：运行中动会话目录会拆坏它的数据库 |
| 目录不在项目根内 | 放行但打醒目警告：`data_dir` 指到项目外了，确认过再加 `--yes` |
| 目录里没有 `td.binlog` | 拒绝：那多半不是 TDLib 的数据目录（`data_dir` 指错了），要删请自己手工删 |

```text
$ fuyubot logout --config demo\fuyubot.toml
将要删除 TDLib 本地会话（logout）：
  目录  demo\data
  内容  3 个文件，1.2 MB
  条目  td.binlog、db.sqlite、db.sqlite-wal

删掉之后 session 就没了，下次 `fuyubot run` / `fuyubot login` 要重新登录
（Bot Token / 手机号 / 密码从来不落盘，这里只有 TDLib 的数据库与 binlog）

没有 --yes：上面这些**一个都没删**（这只是预览）。确认要清掉会话就加 --yes 再跑一次。
```

## `status` / `stop`

```powershell
.\fuyubot.exe status --config demo\fuyubot.toml
.\fuyubot.exe stop   --config demo\fuyubot.toml
```

```text
demo：运行中
  pid        64852
  已运行     0 秒
  版本       0.1.0
  名字       mybot
  插件       1 个
  日志       demo\logs\fuyubot.log
```

`status` 只读 `<项目根>/.fuyubot/`，三态：运行中 / 启动中 / 没有运行中的实例（顺带报「上次」的 pid）。
`stop` 是**优雅**的：写 `.fuyubot/stop` 请实例自己收摊（停接收循环 → 卸载插件 → 停内核 → 放锁），
8 秒不理会才硬杀。

```text
已停止 mybot（pid 64852，优雅退出：插件 stop 与内核都已收摊）
```

## `config`

```text
fuyubot config [--config <CONFIG>]
```

打印**生效值**：默认值填好之后每一项到底是什么，外加「向上找到的那份 `fuyubot.toml`」。
不加载插件、不接 TDLib、不建任何东西。

```text
$ fuyubot config --config demo\fuyubot.toml
配置文件  demo\fuyubot.toml
项目根    demo
[bot]       name         = mybot
[telegram]  account_type = bot
[telegram]  api_id       = 12345
[telegram]  api_hash     = 已保存在本文件（不回显）
[telegram]  data_dir     = demo\data
[plugins]   dir          = demo\plugins
[plugins]   log_level    = info（默认）
[tdlib]     path         = 自动（TDLIB_TDJSON_PATH → 自带 → exe 同级 → 系统库 → 裸库名）
[tdlib]     log_verbosity= 1
凭据        Bot Token / 手机号 / 密码不落盘（TG_BOT_TOKEN 或交互输入）
[plugin.fuyubot.manage] = { reply_prefix = "已安装插件：" }
```

- 文件不存在时第一行会写「（不存在，下面全是默认值）」——`run` 就是这样起的，不骗人。
- `account_type` 写错**不会**静默当 bot：那一行直接是 `⚠️ [telegram].account_type = "robot" 认不出来，只能写 "bot" 或 "user"`。
- 每个 `[plugin.<插件名>]` 段各占一行（插件名是点分的，所以显示成 `[plugin.fuyubot.manage]`）；没有插件段时写「无（没有 `[plugin.*]` 段）」。
- 没有 `get` / `set` / `path`：改配置用编辑器更直接，路径 `status` 第一行已经打了。**插件**读写配置走 ABI 的 `get_config` / `set_config`（见[插件 ABI](../plugin/abi.mdx)），不是这个子命令。

## `plugin`

| 命令 | 作用 |
| --- | --- |
| `fuyubot plugin list [--config …] [--plugin-dir <目录>]` | 列出插件；脚本插件会**展平到每个脚本** |
| `fuyubot plugin install <文件或目录> [--config …] [--plugin-dir <目录>]` | 装一个插件：传**目录**是脚本插件，传**文件**是原生插件 |
| `fuyubot plugin uninstall <名字> [--config …] [--plugin-dir <目录>]` | 卸载：脚本插件按**目录名**，原生插件按动态库名 |

```text
$ fuyubot plugin install ./my-plugin
已安装 plugins\scripts\my-plugin

$ fuyubot plugin list
fuyubot.js-host  ABI 4  plugins\fuyubot_js_host.dll
fuyubot.python-host  ABI 4  plugins\fuyubot_python_host.dll
脚本插件（1 个，由中间插件托管）：
  mybot.my-plugin  python  plugins\scripts\my-plugin\main.py

$ fuyubot plugin uninstall my-plugin
已卸载 plugins\scripts\my-plugin
```

- **脚本插件**（推荐，见 [脚本插件](../plugin/scripts.mdx)）：传的是**整个目录**
  （里面有 `pyproject.toml` / `package.json` 身份段），装到 `plugins/scripts/<目录名>/`。
  目标已存在会报错，要覆盖先 `uninstall` 再 `install`。
- **原生插件**：传编好的 `.dll` / `.so` / `.dylib`，或**工程目录**。传目录时按
  `<工程>/target/{release,debug}` → 工程目录本身 → **沿父链最近的** `target/{release,debug}`
  这个顺序找产物（两边都有时取**较新**的那个）。最后一档就是给 workspace 成员准备的
  （`cargo build -p <crate>` 的产物落在仓库根 `target/`，工程自己那份 `target/` 根本不存在），
  所以那种情况**直接传工程目录就行**，没有 `--target-dir` 这个参数。产物连同旁边 / 工程根的
  `.py` / `.js` / `.ts` / `.pyi` 同伴脚本一起拷进插件目录。
- `list` 会**真的加载一次**动态库才知道名字，但**只发现不启动**脚本——不装依赖、
  不起进程，随时可以跑。脚本的名字取自 manifest（`name` 字段），路径是入口文件。
- `uninstall` 对**跑着的实例也安全**：文件删掉后目录 watch 会自动卸载对应脚本，
  不需要先 `stop`。
