fuyubot 命令参考

运行时 CLI：init / run / status / stop / config / plugin

跑框架的那个 CLI。它就是运行时包里的 fuyubot(.exe)（从源码跑时是 target/{debug,release}/fuyubot）。

init

参数默认说明
--dir.项目目录，生成 <dir>/fuyubot.toml 与 <dir>/plugins/
--namefuyubot只影响配置里的 name
--api-id0TDLib api_id（不是秘密，可以写进配置）；0 = 没配，run 会问

init 只写 api_id：api_hash 是凭据，这个命令连参数都没有，配置里也没有这个字段。 重复 init 会被挡住（不覆盖你改过的配置）。

run

参数作用
--config配置文件，默认 fuyubot.toml（缺这个文件时 run 会按模板自动生成一份）
--plugin-dir覆盖 [plugins].dir
--no-tdlib不接 TDLib，只加载插件
--no-login接 TDLib 但不走登录流程（已有 session 照样能用；CI / 容器用）
--background派生无终端的子进程，stdout/stderr 进 logs/fuyubot.log，父进程等状态发布后返回
--replay <文件>把一批更新 JSON 灌进管线后退出：不接 TDLib、不用账号
--replay-wait <MS>回放后等插件的静默窗口；不填按插件形态自选（脚本插件 2000，原生 150）

run 不带 --replay 的顺序：自动 init → 拿单实例锁 → 问/读凭据 → attach TDLib → 加载全部插件 → 发 setTdlibParameters 并登录 → getMe 打印账户 → 发布状态 → 才开始分发。 登录这一步没有真账号端到端验过，要立刻验插件就用 --replay。

后台运行没有 stdin：没有 session 又没有 TG_BOT_TOKEN 时会直接失败并把日志尾巴打出来—— 先用前台登录一次（session 落在 data/）。

status / stop

status 只读 <项目根>/.fuyubot/，三态：运行中 / 启动中 / 没有运行中的实例（顺带报「上次」的 pid）。 stop 是优雅的：写 .fuyubot/stop 请实例自己收摊（停接收循环 → 卸载插件 → 停内核 → 放锁）， 8 秒不理会才硬杀。

config

打印生效值：默认值填好之后每一项到底是什么，外加「向上找到的那份 fuyubot.toml」。 不加载插件、不接 TDLib、不建任何东西。

  • 文件不存在时第一行会写「（不存在，下面全是默认值）」——run 就是这样起的，不骗人。
  • account_type 写错不会静默当 bot：那一行直接是 ⚠️ [telegram].account_type = "robot" 认不出来，只能写 "bot" 或 "user"。
  • 没有 get / set / path：改配置用编辑器更直接，路径 status 第一行已经打了。

plugin

命令作用
fuyubot plugin list [--config …] [--plugin-dir <目录>]列出插件目录里能加载的插件（会真的加载一次再看名字）
fuyubot plugin install <文件或工程目录> [--config …] [--plugin-dir <目录>]把编好的产物（+ 同伴脚本）复制进插件目录

传工程目录时会去 <工程>/target/{release,debug} 找产物，并把工程根目录的 .py / .js / .ts / .pyi 一起拷走；传单个 .dll 时只扫 dll 旁边——脚本插件请传目录。 workspace 成员的产物默认落在仓库根 target/ 下，这种情况加 --target-dir 或直接指着产物装。
