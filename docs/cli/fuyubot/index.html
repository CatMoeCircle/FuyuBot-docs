fuyubot 命令参考

运行时 CLI：init / run / status / stop / config / plugin

跑框架的那个 CLI。它就是运行时包里的 fuyubot(.exe)（从源码跑时是 target/{debug,release}/fuyubot）。

init

参数默认说明
--dir.项目目录，生成 <dir>/fuyubot.toml 与 <dir>/plugins/
--namefuyubot只影响配置里的 name
--api-id0TDLib api_id（不是秘密，可以写进配置）；0 = 没配，run 会问

init 只写 api_id：api_hash 这个命令连参数都不收（init 阶段手上不该有它）——run 首次会问，问完写回配置。 重复 init 会被挡住（不覆盖你改过的配置）。

run

参数作用
--config配置文件，默认 fuyubot.toml（缺这个文件时 run 会按模板自动生成一份）
--plugin-dir覆盖 [plugins].dir
--api-id <ID>覆盖配置里的 api_id（不是秘密，可以写在命令行 / 脚本里）。优先级：--api-id → TG_API_ID → 配置 [telegram].api_id → 交互提问。api_hash 没有对应参数（只走 TG_API_HASH 或交互输入）
--no-tdlib不接 TDLib，只加载插件
--no-login接 TDLib 但不走登录流程（已有 session 照样能用；CI / 容器用）
--background派生无终端的子进程，stdout/stderr 进 logs/fuyubot.log，父进程等状态发布后返回
--replay <文件>把一批更新 JSON 灌进管线后退出：不接 TDLib、不用账号
--replay-wait <MS>回放后等插件的静默窗口；不填按插件形态自选（脚本插件 2000，原生 150）

run 不带 --replay 的顺序：自动 init → 拿单实例锁 → attach TDLib → 问/读凭据 → 加载全部插件 → 发 setTdlibParameters 并登录 → getMe 打印账户 → 发布状态 → 才开始分发。 登录这一步没有真账号端到端验过，要立刻验插件就用 --replay——想单独把登录走完（不起框架）用 login。

后台运行没有 stdin：没有 session 又没有 TG_BOT_TOKEN 时会直接失败并把日志尾巴打出来—— 先用前台登录一次（session 落在 data/）。

login

只登录，不起框架：建 TDLib 客户端 → 走完授权 → 打印账户 → 退出。不加载插件、不开接收循环。 session 落在 data/，之后 fuyubot run（含 --background）起来就直接进 Ready——后台跑没有 stdin、 登录问不了，先前台 login 一次正是给这条路准备的。

参数作用
--config配置文件，默认 fuyubot.toml（缺文件时同样会自动生成一份）
--api-id <ID>与 run 的 --api-id 同义、同优先级（--api-id → TG_API_ID → 配置 → 提问）

凭据解析、授权状态机、账户打印全部复用 run 的那套，两条路不会漂移。两条额外限制：

  • 实例在跑时拒绝：TDLib 的 sqlite + binlog 同一时刻只能一个进程打开，login 再开一次会把跑着的实例拆坏。
  • TDLib 没就绪就报错退出，告诉你缺什么（TDLIB_TDJSON_PATH / exe 同级 tdjson / [tdlib].path）。

logout

清掉本地 TDLib 会话目录（= [telegram].data_dir，默认 <项目根>/data，里面是数据库与 binlog）＝ 退出登录， 下次要重新登录。默认只打印将要删除什么，加 --yes 才真删。

它只清本地：不发服务端的 logOut（Telegram 那边的会话还在，只是本机这份没了）。

参数作用
--yes真的删除。不加就是预览，一个文件都不动

三道守卫与 --yes 无关，命中就拒绝：

守卫行为
实例在跑拒绝（预览前、真删前各挡一次）：运行中动会话目录会拆坏它的数据库
目录不在项目根内放行但打醒目警告：data_dir 指到项目外了，确认过再加 --yes
目录里没有 td.binlog拒绝：那多半不是 TDLib 的数据目录（data_dir 指错了），要删请自己手工删

status / stop

status 只读 <项目根>/.fuyubot/，三态：运行中 / 启动中 / 没有运行中的实例（顺带报「上次」的 pid）。 stop 是优雅的：写 .fuyubot/stop 请实例自己收摊（停接收循环 → 卸载插件 → 停内核 → 放锁）， 8 秒不理会才硬杀。

config

打印生效值：默认值填好之后每一项到底是什么，外加「向上找到的那份 fuyubot.toml」。 不加载插件、不接 TDLib、不建任何东西。

  • 文件不存在时第一行会写「（不存在，下面全是默认值）」——run 就是这样起的，不骗人。
  • account_type 写错不会静默当 bot：那一行直接是 ⚠️ [telegram].account_type = "robot" 认不出来，只能写 "bot" 或 "user"。
  • 每个 [plugin.<插件名>] 段各占一行（插件名是点分的，所以显示成 [plugin.fuyubot.manage]）；没有插件段时写「无（没有 [plugin.*] 段）」。
  • 没有 get / set / path：改配置用编辑器更直接，路径 status 第一行已经打了。插件读写配置走 ABI 的 get_config / set_config（见插件 ABI），不是这个子命令。

plugin

命令作用
fuyubot plugin list [--config …] [--plugin-dir <目录>]列出插件；脚本插件会展平到每个脚本
fuyubot plugin install <文件或目录> [--config …] [--plugin-dir <目录>]装一个插件：传目录是脚本插件，传文件是原生插件
fuyubot plugin uninstall <名字> [--config …] [--plugin-dir <目录>]卸载：脚本插件按目录名，原生插件按动态库名
  • 脚本插件（推荐，见 脚本插件）：传的是整个目录 （里面有 pyproject.toml / package.json 身份段），装到 plugins/scripts/<目录名>/。 目标已存在会报错，要覆盖先 uninstall 再 install。
  • 原生插件：传编好的 .dll / .so / .dylib，或工程目录。传目录时按 <工程>/target/{release,debug} → 工程目录本身 → 沿父链最近的 target/{release,debug} 这个顺序找产物（两边都有时取较新的那个）。最后一档就是给 workspace 成员准备的 （cargo build -p <crate> 的产物落在仓库根 target/，工程自己那份 target/ 根本不存在）， 所以那种情况直接传工程目录就行，没有 --target-dir 这个参数。产物连同旁边 / 工程根的 .py / .js / .ts / .pyi 同伴脚本一起拷进插件目录。
  • list 会真的加载一次动态库才知道名字，但只发现不启动脚本——不装依赖、 不起进程，随时可以跑。脚本的名字取自 manifest（name 字段），路径是入口文件。
  • uninstall 对跑着的实例也安全：文件删掉后目录 watch 会自动卸载对应脚本， 不需要先 stop。
