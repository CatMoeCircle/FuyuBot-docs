fuyubot-sdk 命令参考

插件开发 CLI：脚手架 / 生成绑定 / 查 TDLib / 静态检查

写插件用的 CLI，和运行时完全分开：它不碰账号、不加载 TDLib，也不需要 tdjson。

init

生成到 <dir>/plugins/<名字>/；--lang 决定模板：

语言生成什么
rust独立 crate（Cargo.toml 开头有空 [workspace]）+ src/lib.rs（define_plugin!）
c / cpp源码 + fuyubot_plugin.h（从 PLUGIN_HEADER 落的盘，唯一权威源）
pythonsrc/lib.rs（script_plugin!）+ plugin.py + fuyubot_plugin.py(+.pyi)
jssrc/lib.rs + plugin.js + fuyubot_plugin.js(+.d.ts)

生成的 Rust 插件默认写 fuyubot-plugin-api = "0.1.1"（crates.io）。想对着 SDK 源码开发就设 FUYUBOT_SDK_PATH 指向 SDK 仓库里放着 crate 的目录（crates/），生成器会改写成 path = …； 没设且本地找不到源码时只写版本号。

codegen

刷新某门语言的 ABI 绑定文件到 <dir>：C / C++ 是 fuyubot_plugin.h，Python 是 fuyubot_plugin.py + .pyi，JS 是 fuyubot_plugin.js + .d.ts。会覆盖同名文件。 所有语言都来自同一份权威源（fuyubot_abi::PLUGIN_HEADER 与 fuyubot-sdk-script 里的桥）， 不是手抄的第二份。--lang rust 没有可生成的绑定，命令会说明。

check

静态读 PE / ELF / Mach-O 的导出表（用 object，绝不 dlopen——加载会在宿主进程里跑插件的 初始化代码，那已经算「运行」了）。非零退出码 = 宿主会拒绝加载（缺 plugin_init，或根本不是动态库）。

check 静态看不到 PluginHandle.abi_version——版本是 plugin_init 的返回值，不是静态符号。 它只会如实报「宿主是 vN，插件的版本只能运行时判定」，别把它当兼容性结论。

abi-version / td-methods / td-method / td-types

td-methods / td-method / td-types 吃的都是编译期烤进二进制的真 td_api.tl 元数据 （TdApiSchema::compiled()），不读文件、不联网。--filter 是子串匹配、忽略大小写；构造器不能当方法调， td-method 会明确拒绝。

td-types 给 on / invoke 生成精确类型：写到 --out <目录> 下的 td_api.d.ts（覆盖同名文件， 默认当前目录）。只有 JS / TS 插件用得上它。

TDLib 的方法名 ≠ Telegram Bot API 的：所有发送都是 sendMessage + input_message_content， sendPhoto / sendDocument 之类在 TDLib 里不存在。写请求前先用 td-method 核一遍。
