插件分发格式 v1

plugins/<id>/plugin.json、静态探测、CLI 安装与商店索引契约

状态：已落地（2026-11-03）。这份文件是并行开发的接口契约： fuyubot-loader 与 fuyubot-cli 两侧按它实现，任何偏离先改这份文件。

非目标（加载器 / 运行时不做）：商店索引 / 网络下载 / zip 解压 / 签名 / plugins.lock。 这些只在 CLI 的 TUI 商店（crates/fuyubot-cli/src/panel/store.rs）里；商城后端属于 P1， 见 插件商店与分发。

1. 目标

  1. 一个插件 = 一个目录，目录里有 plugin.json（静态元数据）。
  2. 宿主不 dlopen 就能列举、校验、排序插件。
  3. 旧形态（平铺 *.dll / plugins/scripts/<name>/）继续可用，给 plugin migrate 迁移。
  4. ABI 不变（仍是 v5，四个导出符号与 VTable 一个都不动）。

2. 目录布局

规则：

  • 原生包扫描 plugins/*/plugin.json（只下一层，不递归）。
  • 脚本包扫描 plugins/scripts/*/plugin.json（同样只下一层），只用于列举； 真正的发现/启停仍由 SDK 的 fuyubot_python_host / fuyubot_js_host 负责。
  • 以 . 开头的目录（.disabled / .staging / .cache）一律跳过。
  • 名字以 .disable 结尾的目录也跳过（旧面板把目录改名禁用留下的历史形态）。
  • 目录名必须等于 plugin.json 的 id；不一致时以 id 为准并告警。
  • 禁用 = 整个目录挪到 plugins/.disabled/<id>/，不写第二份清单。

3. plugin.json

字段：

字段必填说明
schema是目前只认 1；更大 → UnsupportedSchema
id是[A-Za-z0-9][A-Za-z0-9._-]*，≤128，不含路径分隔符，不以 . 开头
name是展示名（可中文）
version是非空；只允许 [0-9A-Za-z.+-]（不强制 semver 解析，商店阶段再严）
kind是native / python / js
entry是相对包根；禁止绝对路径、..、反斜杠开头；解析后必须仍在包内且是文件
abinative 建议静态预检用的建议值，真值以 plugin_init 返回的 handle 为准
platforms否空 = 全平台；any 也等于全平台；否则必须含 current_platform()
depends否硬依赖（服务名，进内核 inject）
optional_depends否软依赖（进 soft_inject）
provides否本插件提供的服务名（静态预检/商店展示用）
config否默认配置相对路径；P0 只解析不合并
其余否未知字段忽略（向前兼容）

current_platform() 返回 windows-x86_64 / linux-x86_64 / macos-aarch64 这类串， 与发布资产命名一致。

5. Probe / 加载语义

PluginLoader 新增：

  • probe_bundle：读 plugin.json → 校验 → entry_path → 读文件魔数判 Go → 返回 Probe。不调用 open_library / plugin_init。
  • probe（旧）：先 looks_like_go_binary，是 Go 就返回新错误 LoadError::GoRequiresManifest { path }，不 dlopen；否则维持现状。
  • DylibPlugin::probe(loader, path, config)：path.is_dir() → probe_bundle，否则 → probe。
  • DylibPlugin::apply 用 self.entry（不是 self.path）去 start_library。
  • DylibPlugin::abi_version() 返回 Probe.abi_version（bundle 可能是 0，表示“装完才知道”）。

LoadError 新增：

scan_dir / load_dir 改为走 plugin_entries + probe_entry，保持现有返回类型。

6. CLI 行为

fuyubot plugin list

不再 dlopen / 不再创建 Kernel。 输出四段：

  1. 原生包：<id>\t<version>\tABI <n|?>\t<kind>\t<path>
  2. 旧形态 dll：<文件名>\tlegacy\t<path>（读不了元数据，直说）
  3. 脚本包：scripts/<dir> 有 plugin.json 就按它列；没有就按 package.json / pyproject.toml 列
  4. 禁用项：.disabled/<id>/ 与 *.disable

fuyubot plugin install <路径>

  • 目录 + plugin.json：
    • kind = native → 复制到 plugins/<id>/
    • kind = python/js → 复制到 plugins/scripts/<id>/
    • 目标存在 → 报错（不覆盖）
  • 目录无 plugin.json 但 is_script_plugin_dir → 旧行为（scripts/<目录名>/）， 顺手把从 package.json/pyproject 生成的 plugin.json 写进目标（失败不致命）。
  • 文件 dll → 旧行为；Go 且无 sidecar → 报错并指路 plugin migrate。
  • 其它（zip / tar 等归档）→ CLI 不处理，明确报错并指路： 「用 TUI 插件商店安装，或手动解压到 plugins/<id>/」。

fuyubot plugin uninstall <名字>

按顺序找：plugins/<id>/ → plugins/scripts/<id>/ → .disabled/ 下两处 → 旧形态 dll（带不带 lib 前缀、带不带 .disable）。找到就整个目录删。

fuyubot plugin migrate [--dry-run]

  • 平铺 dll：这里允许 dlopen 一次（用户显式触发，进程即将退出）拿 name/version/deps → 建 plugins/<id>/bin/ → 移动 dll + 同主干同伴脚本 （.py/.js/.ts/.pyi）→ 写 plugin.json。
    • id 取 plugin_init 的名字；非法 id（含 / 等）→ 报错跳过。
    • 目标已存在 → 报错跳过，不合并。
    • Go：允许，但打一条「已永久映射，仅本次迁移进程」的说明。
  • scripts/<dir> 无 plugin.json：从 package.json / pyproject.toml 合成 id/name/version/kind/entry 写入（entry 默认 index.ts→index.js / main.py）， 不移动目录。
  • --dry-run 只打印计划。
  • 幂等：已有 plugin.json 的直接跳过。

7. 商城索引（TUI 商店消费的契约）

索引 URL 来自 fuyubot.toml 的 [plugins].registry_url（或环境变量 FUYUBOT_REGISTRY_URL）。索引是静态 JSON，由外部商城托管；本仓只消费，不生成。

规则：

  • schema 只认 1；未知字段忽略。
  • 资产按 current_platform() 精确匹配，找不到再取 any；都没有 = 该平台不可用。
  • sha256 必填（大小写不敏感）；size 可选，只做显示/预检。
  • yanked: true 的版本不参与选择。
  • api 是宿主 fuyubot 的语义版本区间（不是 ABI、也不是 plugin-api 的版本）； P0 的 TUI 商店只做展示/提示，不据此拒绝安装——真正的兼容性以 abi 与运行时校验为准。
  • abi 大于宿主 ABI_VERSION → 明确报「需要更新的宿主」，不下载。
  • 下载 URL 只允许 https；解压时必须防 zip-slip / 符号链接 / zip bomb （单包 ≤ 50MB、解压后 ≤ 200MB、文件数 ≤ 2000）。
  • 解压后必须用 BundleManifest 再校验一次 id / version / entry / 平台。

8. 约束

  • 不改 ABI：fuyubot-abi 一行不动。
  • 不递归扫描：node_modules / .venv 绝不能进扫描。
  • 不改脚本插件根：plugins/scripts/ 保持，SDK 中间插件不动。
  • 路径一律 Path，不拼字符串；Windows 反斜杠要兼容。
  • 测试临时目录用 target/test-tmp/...（仓库约定），不要用系统 TEMP。
  • 所有新增公开项要有 rustdoc；错误信息要能指导用户下一步。
  • 改动后至少 cargo test -p fuyubot-loader --offline / cargo test -p fuyubot-cli --offline / cargo fmt --all --check 通过。
