插件分发包

目录结构、plugin.json 字段，以及安装到机器人里的方法

一个原生插件就是一个目录：根上放 plugin.json，入口和依赖放在 bin/。 脚本插件仍然是一个目录，放在 plugins/scripts/ 下。

入口文件名不限，plugin.json 的 entry 指向哪个人就用哪个。Windows 是 .dll， Linux 是 .so，macOS 是 .dylib。

plugin.json

最小可用的原生插件清单：

字段必填说明
schema是固定 1
id是插件唯一标识，只能用字母、数字、.、_、-，最长 128；不能以点结尾
name是展示名
version是语义化版本，和发布 tag 一致
kind是native / python / js
entry是相对包根的入口路径，必须真的存在
abi建议编译时使用的宿主 ABI 版本；不写则加载后才知道
platforms否为空或 ["any"] 表示全平台；否则必须包含当前平台
depends否硬依赖的服务名，例如 ["help.commands"]
optional_depends否软依赖的服务名
provides否本插件提供的服务名，供展示与依赖检查
config否默认配置文件的相对包根路径（如 config.default.toml）。加载时并进 [plugin.<id>]，优先级最低：用户配置与插件运行时落盘已有的键不会被覆盖
description否一句话说明，显示在插件列表 / 商店
license否许可证标识
homepage否项目主页

id 也决定配置段：[plugin.com.example.weather]。三层优先级（包默认 < 运行时落盘 < 用户配置）与 set_config 的写规则见配置文件 · 插件自己的配置段。

打包成 zip

发布时打一个 zip，zip 根就是插件目录的内容，不要套一层目录：

打包要求：

  • 只放运行需要的东西：不要带 node_modules/、.venv/、target/、.git/；
  • 不要放符号链接；
  • 单个 zip 不超过 50MB，解压后不超过 200MB，文件数不超过 2000；
  • 文件名不要以点或空格结尾，不要用 CON、NUL、COM1 这类 Windows 保留名 （大小写也算冲突）；
  • 资产名建议 <id>-<version>-<平台>.zip，例如 com.example.weather-1.2.0-windows-x86_64.zip；纯脚本包用 -any.zip。 Android 用 android-aarch64 / android-x86_64，入口是 .so（例如 bin/libweather.so），不能拿 Linux 的包代替。

商城按资产名和 plugin.json 校验，不符合上面的规则会被拒绝收录。

安装

从商店安装

新建项目默认已配置官方商店（fuyubot.toml 的 [plugins].registry_url）。 换商店改那一行，删掉则关闭商店。

运行 fuyubot run --tui，进「商店」页搜索、选中、安装，然后重启实例。

本地目录安装

原生包装进 plugins/<id>/，脚本包装进 plugins/scripts/<目录名>/。 也可以用 fuyubot plugin install 装单个 .dll（旧形态），但推荐目录包。

排查

现象原因 / 处理
plugin list 看不到目录不在 plugins/ 下，或 plugin.json 读不了；确认路径与权限
提示 id 与目录不一致目录名和 plugin.json 的 id 不同会以 id 为准；改名保持一致
提示平台不匹配压缩包不是给当前系统的；换对应平台的资产
提示入口不存在entry 写错，或打包时漏了 bin/ 里的文件
启动时报 ABI 不匹配插件编译时的 ABI 与宿主不一致；用与宿主同版本的 fuyubot-abi 重新编译
加载后名字对不上plugin_init 返回的名字必须等于 plugin.json 的 id

卸载

只删插件目录，[plugin.<id>] 配置和 data/plugins/<id>/ 不会被删。
