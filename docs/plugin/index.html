插件开发约定

帮助你在 plugins/ 目录中快速编写、加载与调试自定义插件。

插件规则

  • 明白插件被 PluginManager 识别的规则；
  • 实现必需的接口与生命周期；
  • 注册命令、更新处理器以及可选的定时/手动运行任务；
  • 借助项目提供的 TDLib 封装函数提升开发效率。

插件分两种形态：包插件（目录 + package.json 清单，推荐）与单文件插件（顶层 .ts，元数据写在类上）。从旧格式升级请看插件迁移指南。

1. 插件加载约定

  • 默认目录：PluginManager 扫描 ./plugins 顶层条目。
  • 导出要求：默认导出一个继承自 Plugin 的类。
  • 入口格式：
    • 单文件：plugins/foo.ts
    • 目录：plugins/bar/index.ts（或 package.json 的 main）

1.1 加载顺序

禁用：包插件在读取 package.json 的 name 后即排除，不会 import；配置里的禁用名与此一致。

1.2 包插件（推荐）

目录需带 package.json，复用 name/version/description，并用 pluginType / pluginDependencies 声明插件专有字段：

入口通过包名获取契约类型：

  • name：运行时 id（禁用列表、依赖声明、注册键）。
  • pluginDependencies：填写其他插件的 name，框架保证依赖先加载。
  • 契约包：@fuyu-tdbot/plugin-api（Plugin、PluginAPI、PluginInfo、CommandDef 等）。

1.3 单文件插件

无需 package.json，元数据写在类字段上，最后加载：

构造函数签名：constructor(client: Client, api?: PluginAPI)。

1.4 路径别名导入

框架仓库内可用下列别名（由根 tsconfig 与 node/loader.ts 解析）：

别名实际路径用途说明
@log/*src/log/*日志
@plugin/*src/plugin/*框架插件内部工具（单文件契约亦可）
@TDLib/*src/TDLib/*TDLib 封装和接口
@type/*src/types/*共享类型
@function/*src/function/*通用函数
@db/*src/Database/*数据库 / 配置
@utils/*src/utils/*工具

插件契约（Plugin 等）优先使用包名 @fuyu-tdbot/plugin-api，便于日后独立仓库开发。
