原生插件：七个导出符号

一个原生插件 = 一个 cdylib。宿主 dlopen 它，只认这七个导出符号， 其余全部能力都经 HostApiVTable 回调宿主。插件不认识 Rust 内核，也不需要认识。

符号必须吗干什么
plugin_init必须校验 VTable、构造插件状态；返回失败句柄（abi_version == 0）= 拒绝加载
plugin_start可选拿到配置 JSON，注册订阅 / 工具 / 中间件
plugin_stop可选卸载前调一次，回收自己的状态
plugin_free_string必须释放插件自己分配的字符串（宿主从不 free 插件的指针）
plugin_manifestv4 可选返回自描述 JSON（名字 / 版本 / inject / soft_inject）。宿主在 plugin_init 之前读它来决定激活顺序
fuyubot_abi_versionv4 可选静态返回编译期 ABI_VERSION，fuyubot-sdk check 靠它
plugin_free_handlev4 可选只在 ABI 版本不匹配时被调——那一刻不能调 plugin_stop，只能用它把 init 分配的状态还回来

契约细节（字段布局、内存所有权、版本协商、服务作用域）见 ABI 契约。

最小闭环（原生插件）

  • fuyubot init 重复执行会被挡住（不覆盖你改过的配置）；三个键都有默认值，最简可以只有 [bot]。
  • 插件名只允许字母、数字和 . _ -（会拼进源码与 TOML）；目录名里的 . / - 换成 _ 当 crate 名 （fuyubot.weather → fuyubot_weather）。
  • 产物落在哪：plugin install <工程目录> 按 <工程>/target/{release,debug} → 工程目录本身 → 沿父链最近的 target/{release,debug} 找产物（两边都有时取较新的）。插件若是当前 workspace 的成员， cargo build -p <crate> 默认把产物放在仓库根的 target/，靠最后一档照样能找到，不需要额外参数。
  • SDK 走源码开发时设 FUYUBOT_SDK_PATH 指向 FuyuBot-SDK 仓库的 crates/，生成的插件会写 path = "…"； 不设就写 crates.io 版本号。

fuyubot 管运行，fuyubot-sdk 管开发，两个都不编译插件：编译是作者自己语言工具链的事 （cargo build / cl /LD / gcc -shared）。fuyubot plugin install 只复制已编好的产物。

写原生插件要知道的六件事

事说明
回调是 extern "C-unwind"用 extern "C" 的话，逃出去的 panic 直接 abort 整个进程，宿主来不及 catch_unwind
一个 crate 只展开一次 define_plugin!七个符号名是 ABI 定死的，展开两次就是重复定义
ABI 版本目前是 4不匹配时宿主拒绝加载，不能调 plugin_stop，但会调 plugin_free_handle 把状态还回来
订阅句柄必须活着Rust 侧是 #[must_use] 的守卫，drop 就是退订
插件 emit 不是广播只送自己 + 全局订阅者（emit_scoped），影响别的插件要靠订阅
谁分配谁释放宿主绝不 free 插件的指针；宿主给的字符串是线程局部缓冲，下次宿主调用前有效

声明依赖：inject 与 soft_inject

manifest 里能声明两个列表，它们决定宿主什么时候让你跑、以及跑的顺序：

字段意思缺了会怎样
inject硬依赖不激活。停在 Pending 等着，等你缺的东西出现
soft_inject软依赖照常激活，只是排在「软依赖也齐了」的插件后面

依赖名可以写两种东西，宿主都认：

  • 服务名 —— 比如 "storage.mongo"，宿主查 Context 里有没有这个名字
  • 插件名 —— 比如 "fuyubot.manage"，宿主查同名插件是不是 Active

三件事值得先记住：

  1. Pending 不是失败。 它表示「还没轮到」或「等的东西还没来」。真正的失败只有两种： 你的 plugin_start 报错，或者你依赖的提供者已经 Failed（那时你也会被级联标成 Failed）。
  2. 软依赖不保证顺序。 它只是排序偏好：软依赖齐的先上，不齐的也照样上，只是排后面。 要「他必须先于我」就写 inject，别用 soft_inject。
  3. 依赖是准入，不是注入。 宿主不会把那个服务的引用塞给你——你仍然自己去 get_service 拿。inject 只保证「轮到我的时候它一定在」。

排查看 fuyubot status：pending 那一栏会列出插件名和它还缺哪些。

插件名与目录

  • 插件名只允许字母、数字和 . _ -（它会拼进源码和 TOML）；目录名里的 . / - 换成 _ 当 crate 名 （fuyubot.weather → fuyubot_weather）。
  • 原生插件名只有 dlopen 之后才知道：它来自 plugin_init 返回的 PluginHandle，所以 fuyubot plugin list 会真的加载一次再看名字。
  • 脚本插件的身份在 manifest 里（Python 的 [tool.fuyubot] / JS 的 "fuyubot" 段）， 目录名是装卸载的单位（fuyubot plugin install|uninstall <目录>），见 脚本插件。
