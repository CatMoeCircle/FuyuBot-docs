调试与安装

回放验证、静态检查、装进插件目录

插件出问题通常不是「代码写得不对」，而是「没被加载」「加载了但没订阅上」「订阅了但请求拼错」。 这三步各有对应的工具，全都不需要 Telegram 账号。

命令干什么需要账号吗
fuyubot-sdk check <产物>静态读导出符号，不 dlopen否
fuyubot run --replay <文件>把一批更新灌进管线后退出，不接 TDLib否
fuyubot plugin install <路径>复制产物（＋脚本同伴）进插件目录否
fuyubot plugin list真的加载一次，看插件名与 ABI 版本否
fuyubot run真登录、真更新是

静态检查：fuyubot-sdk check

  • 非零退出 = 宿主会拒绝加载（缺必需的 plugin_init，或根本不是动态库），可以进 CI。
  • 它不加载、不运行：走 object 解析 PE / ELF / Mach-O 的导出表，不碰 dlopen （dlopen 会在宿主进程里跑插件的初始化代码，那已经算「加载」了）。
  • 因此它看不到 ABI 版本——版本是 plugin_init 的返回值，不是符号。它只会如实报 「只能运行时判定」，不编一个看起来可信的结论。

回放：不接账号也能验插件

回放把文件里的更新（单个对象或对象数组）灌进六阶段管线后退出：不接 TDLib、不用账号， 插件发出的请求只留档不发。输出三样东西：

  1. 每条更新的 UpdateOutcome：
  1. 插件打的日志（HostRuntime::log_lines，上限 256 行）；
  2. 插件发出去的请求：#请求号 方法名 参数。
参数说明
--replay <文件>要回放的更新；对象或对象数组
--plugin-dir <目录>覆盖插件目录（默认取 fuyubot.toml 的 plugins.dir）
--replay-wait <MS>回放后的静默窗口；不填时脚本插件 2000ms、纯原生插件 150ms（上限 60 秒）

脚本插件在另一个进程里跑，反应要经管道回来，还可能捎带网络请求——窗口太短会把最终答复漏掉。

回放故意不接 TDLib：它要在任何机器上离线可跑，接了就要账号与网络。 所以回放能证明「插件收到更新后做出了正确判断、发出了正确请求」，不能证明真 Telegram 认这些参数。

安装

  • 传工程目录时会把旁边的 .py / .js / .ts / .pyi 一起拷；传单个 dll 时看不到脚本在哪， 脚本插件请传工程目录。
  • plugin install <工程目录> 只看 <工程>/target/{release,debug} 与工程目录本身。若插件是当前 workspace 的成员（本仓的 examples/*），cargo build -p <crate> 的产物默认落在仓库根 target/， 于是它找不到——加 --target-dir <工程目录>/target，或直接指着产物装。

装完还是不响？

症状先看
check 报 [缺] plugin_initcrate 是不是 crate-type = ["cdylib"]；C++ 的四个符号在不在 extern "C" 里
日志里有「跳过 xxx」ABI 版本不匹配，或 dlopen 失败（缺兄弟 DLL：把依赖放在插件旁边，加载器会先查库自己的目录）
加载了但一条事件都没收到订阅句柄是不是被 drop 了（Rust 侧 let _ = 会立刻退订）
脚本插件起不来manifest 身份段（[tool.fuyubot] / "fuyubot"）与 entry 对不对；run() 是不是最后一行；uv / bun 在不在；原生桥库找不找得到（见 脚本插件常见问题）
请求发出去了但没收到响应回放里本来就不会有响应（请求只留档）；真环境下等的是 "response" 通道，见 调用 TDLib

要查 TDLib 的方法名与参数名，用 fuyubot-sdk td-methods --filter <片段> / td-method <名字>； 契约与所有权规则见 ABI 契约。
