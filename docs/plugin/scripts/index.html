薄 SDK 能干什么

函数干什么
on(事件名, 处理函数)订阅一个事件，来消息时你的函数被调用
invoke(方法, 参数, 回调?)调一次 TDLib 接口（发消息、取资料……）
log(消息, 级别?)打日志，级别：error / warn / info / debug / trace
emit(事件名, 数据?)发一条自己的事件
register_tool(...) / use_middleware(...)注册工具、挂中间件（进阶，见下文按语言页）
run()握手并开始收事件。永远放最后一行

装好之后会发生什么

你做的机器人的反应
fuyubot plugin install <目录>目录整个拷进 plugins/scripts/，下次 run 自动加载
运行中往 plugins/scripts/ 丢一个新目录约一秒内自动发现、装依赖、启动
运行中删掉一个脚本目录自动停掉对应脚本（对跑着的实例也安全）
改了脚本里的代码不自动重启；改完重启机器人即可
fuyubot plugin uninstall <目录名>删掉目录并卸载脚本

名字的两副面孔：manifest 里的 name（如 mybot.my-plugin）是插件身份，日志里看到的是它； plugin uninstall 用的是目录名（my-plugin）。装的时候整个目录一起拷， node_modules / .venv / target 这类依赖与构建产物会被跳过——到机器人上现装。

两种形态怎么选

脚本插件（本页）原生插件
写什么Python / JS / TS 脚本Rust / C / C++ 编译出的动态库
要编译吗不要要（用你自己的工具链）
崩了会怎样只有这个脚本的进程死，机器人照常跑可能拖垮整个宿主
适合机器人逻辑、自动化、小工具高性能、要贴近宿主的场合

原生插件是「一个 cdylib 一个插件」，见 插件总览。

常见问题

脚本报「找不到 fuyubot 原生桥库」：脚本进程要加载 fuyubot_sdk_native （和托管插件是同一份库）。把它放在插件目录里，或设环境变量 FUYUBOT_NATIVE_LIB 指向它的完整路径，再重启机器人。

  • 依赖工具：Python 要装 uv，JS / TS 要装 bun。缺了的话对应脚本起不来，日志里会有提示，但不影响机器人启动。
  • 托管插件：plugins/ 里要有 fuyubot_python_host / fuyubot_js_host 两个中间插件（脚本由它们托管），和内置插件放在一起。
  • 插件名只允许字母、数字和 . _ -。
  • 想排查脚本：把配置里 [plugins].log_level 调成 "debug"（见 配置文件），日志会详细很多。
