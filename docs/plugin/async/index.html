异步等待（await）

Rust 插件里可 await 的请求与更新等待

wait_for_update 是阻塞原语：调用线程停下来等。要 async/await 那种语义， 用下面这层不阻塞的封装——任务挂起，事件到了再唤醒。

本页只讲原生插件。脚本插件（Python / JS / TS）的 invoke_async / wait_async / runAsync 在脚本插件板块。

Rust：ResponseRouter

fuyubot-abi 重导出 ResponseRouter / ResponseFuture / UpdateFuture：

要点：

  • 必须在插件自己的 executor 上 await，别在宿主事件回调里 await（那是接收线程）。
  • router.invoke* 从插件自己的线程发请求时会用 scope service 把归属切回插件， 响应不会丢；不需要手动 scope_enter。
  • simplify op 必须走 invoke_op：宿主侧 op 工作线程不压作用域栈，请求归属在 simplify_invoke 被调用的那一刻就登记了。直接调 host.simplify_invoke 会把归属记成 宿主（owner 0），simplifyResult 只投给全局订阅者，本插件永远等不到。
  • 取消 = drop(fut)；关闭 = drop router（所有 pending 立刻 RouterClosed）。
  • 超时不内建，用 tokio::time::timeout 或你运行时的等价物。

哪些语言有 await

语言怎么写
Rust本页的 ResponseRouter（要有自己的 executor）
C / C++ / Go没有 await：on 回调 + 状态机，或者用语言自己的协程包装同步等待
Python / JS / TS不在这个板块——脚本侧见 Python / JS 与 TypeScript
