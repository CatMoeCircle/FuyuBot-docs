Rust 插件

fuyubot-plugin-api 与 define_plugin! 的完整写法

Rust 插件只依赖一个 crate：fuyubot-plugin-api。它把 fuyubot-abi 的形状转成用着不疼的样子—— HostApi（已解包、调用路径上没有 Option 和 panic 分支）、HostExt 便利方法、 drop 即退订的 Subscription、以及 define_plugin! 宏。

Plugin trait

方法对应符号说明
init(host) -> Result<Self, String>plugin_init构造状态；返回 Err = 加载失败
start(&mut self, config_json) -> Result<(), String>plugin_start宿主已把 VTable、插件目录都准备好；订阅/注册都写在这里
stop(&mut self)plugin_stop可选；宏随后把状态收回 Box 释放

define_plugin! 还会把插件代码包在 catch_unwind 里——和 C-unwind 是两层， 两层都要：一层防 panic 逃出 ABI，一层防 panic 把宿主线程带走。

回调里带状态

回调是裸函数指针，没有捕获环境。状态要么放插件字段、经 user_data 传进去，要么像 examples/rust-echo 那样把 Box<HostApi> 的地址当 user_data：

stop 里用 Box::from_raw 收回，只收一次；否则就是内存泄漏（或重复释放）。

Subscription 是 #[must_use]：let _ = host.subscribe_json(…) 会立刻退订。 一定要存进插件字段。插件卸载时宿主还会整批回滚，但那时插件自己的状态已经漏了。

编译与安装

define_plugin! 一个 crate 只能展开一次。一个 cdylib 就是一个插件——这不是限制，是设计： 四个导出符号名由 ABI 定死，展开两次就是重复定义。

要发消息、调 TDLib、等响应，见 调用 TDLib；要按字段过滤更新，见 订阅与事件；契约本身见 ABI 契约。
