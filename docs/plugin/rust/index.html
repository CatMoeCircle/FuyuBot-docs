Rust 插件

fuyubot-plugin-api 与 define_plugin! 的完整写法

Rust 插件只依赖一个 crate：fuyubot-plugin-api。它把 fuyubot-abi 的形状转成用着不疼的样子—— HostApi（已解包、调用路径上没有 Option 和 panic 分支）、HostExt 便利方法、 drop 即退订的 Subscription、ResponseRouter（可 await 的请求/更新等待），以及 define_plugin! 宏。异步写法见 异步等待。

那个空的 [workspace] 不是多余的：没有它，cargo 会一路往上找父目录的 workspace 声明然后报错。

define_plugin! 还会把插件代码包在 catch_unwind 里——和 C-unwind 是两层， 两层都要：一层防 panic 逃出 ABI，一层防 panic 把宿主线程带走。

读 / 写配置

每个插件在 fuyubot.toml 的 [plugin.<插件名>] 下有自己的一段配置（详见配置文件）。 HostApi 上两个方法直接读写它：

方法作用
get_config(section, key) -> Option<String>读任意段。section 空串读顶层（[bot] 等），key 空串读整段、否则按点路径取键。返回 JSON 文本，找不到就是 None
set_config(key, value_json) -> Result<(), AbiError>写自己的段。没有 section 参数——宿主按调用者身份判定，写不到别人那段。key 空串覆盖整段。成功后写内存并回写 fuyubot.toml

set_config 回写是全量重写 fuyubot.toml——你手写在文件里的注释、空行会被 toml 序列化丢掉。插件写配置属于程序化修改，这是可接受的取舍；要保注释就别让插件运行时去改， 把值手工维护进文件。

回调里带状态

回调是裸函数指针，没有捕获环境。状态要么放插件字段、经 user_data 传进去，要么像 examples/rust-echo 那样把 Box<HostApi> 的地址当 user_data：

stop 里用 Box::from_raw 收回，只收一次；否则就是内存泄漏（或重复释放）。

Subscription 是 #[must_use]：let _ = host.subscribe_json(…) 会立刻退订。 一定要存进插件字段。插件卸载时宿主还会整批回滚，但那时插件自己的状态已经漏了。

一次看全：常用 ABI 怎么调

HostApi 上是 VTable 那 22 个函数的一对一封装，HostExt 另外给了几个「不用自己拼 JSON 字符串」 的便利方法（subscribe_json / invoke_value / call_tool_value / config_value / set_config_value / wait_for_update_json / info|warn|error）。下面这段把它们用了一遍 （省掉了 user_data 取 HostApi 的样板，见上面「回调里带状态」一节）：

想干什么用哪个
订阅 / 退订subscribe_json（返回 Subscription，drop 即退订）/ 句柄 off
发 TDLib 请求invoke_value(method, params)（或底层 td_invoke_simplified 吃字符串）
同步执行td_execute（parseTextEntities / getTextEntities 这类）
等一条更新 / 一条响应wait_for_update_json（阻塞）或 ResponseRouter 的 await 版，见异步等待
工具register_tool / register_tool_meta / call_tool / call_tool_result / list_tools
服务provide_service（自己作用域）/ provide_service_shared（进程级）/ get_service
配置get_config / set_config（字符串版）、config_value / set_config_value（Value 版）
中间件use_middleware(Stage::X as u32, cb, user_data)
看别人list_tools / list_plugins
跨语言简化入口（v5）simplify_invoke(op_json) / simplify_invoke_result(op_json)——和 JS/TS/Python/Go/C 同一条 op 表（见 ABI › simplify 操作表）；要类型安全的封装仍可用上面的 fuyubot-simplify crate

用封装层发消息：fuyubot-simplify

上面 ⑦ 那种手写 JSON 能跑，但每个方法都要自己拼嵌套结构、还要自己等「发送结局」。 Rust 插件可以直接用封装层——只有 Rust 有这个（它是 crate，不是 ABI）：

它只简化输入，不改变输出：每个方法仍经 td_invoke* 发出，原始更新照旧对插件可见。 完整 API（发送 / 相册 / 编辑 / 富消息 / 命令解析）见 Simplify 封装。 ⚠️ 在更新回调里不能用这些等待版——等更新要靠接收循环那个线程送回来，而回调就跑在它上面； 回调里请用 *_then，见异步等待。

编译与安装

define_plugin! 一个 crate 只能展开一次。一个 cdylib 就是一个插件——这不是限制，是设计： 七个导出符号名由 ABI 定死，展开两次就是重复定义。

要发消息、调 TDLib、等响应，见 调用 TDLib；要按字段过滤更新，见 订阅与事件；契约本身见 ABI 契约。
