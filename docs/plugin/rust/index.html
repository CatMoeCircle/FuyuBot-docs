Rust 插件

依赖 fuyubot-abi，实现 Plugin trait + define_plugin! 的最小写法

Rust 插件只依赖一个 crate：fuyubot-abi。 它给出 HostApi（VTable 的 Rust 封装）、Plugin trait、define_plugin! 宏与 ResponseRouter；没有第二层 SDK——写插件就是实现一个 trait，再把 C ABI 导出交给宏。

那个空的 [workspace] 不是多余的：没有它，cargo 会一路往上找父目录的 workspace 声明然后报错。 fuyubot-abi 走独立版本线（不跟 bot 的版本号，当前 0.1.3）；ABI 契约版本是 fuyubot_abi::ABI_VERSION（当前 6），编辑器里补全一下就有，别手抄。

最小可用插件

define_plugin!(类型, "插件名") 展开出七个导出符号 （plugin_init / plugin_start / plugin_stop / plugin_free_string / plugin_free_handle / fuyubot_abi_version / plugin_manifest）， 并把插件的名字、crate 版本、inject / soft_inject 填进 plugin_manifest。

Plugin trait

方法对应符号说明
init(host) -> Result<Self, String>plugin_init构造状态；返回 Err = 拒绝加载
start(&mut self, config_json) -> Result<(), String>plugin_start订阅 / 注册都写在这里；config_json 是宿主传来的配置
stop(&mut self)plugin_stop可选，回收 Box::into_raw 之类的状态
inject() -> Vec<String>plugin_manifest硬依赖：缺了不激活
soft_inject() -> Vec<String>plugin_manifest软依赖：只影响排队顺序

define_plugin! 还把 init / start / stop 包在 catch_unwind 里——和回调的 C-unwind 是两层，两层都要：一层防 panic 逃出 ABI，一层防 panic 把宿主线程带走。

回调与状态

回调是裸函数指针，没有捕获环境。状态要么放插件字段、经 user_data 传进去：

订阅句柄不会在 drop 时自动退订——SubscriptionHandle 只是个 u64。 要提前退订就留住它、调 host.off(handle)；插件卸载时宿主会整批回滚， 但 user_data 指向的状态还是得自己释放。

读 / 写配置

每个插件在 fuyubot.toml 的 [plugin.<插件名>] 下有自己的一段（见配置文件）。

plugin_start 收到的 config_json 不是这一段。那是宿主给的运行环境信息 （plugins_dir / scripts_dir / spawn 等）；你自己的配置用 get_config("", key) 读（空 section = 自己那段）。

方法作用
get_config(section, key) -> Option<String>读配置。section 用配置文件里的段名（plugin.my.weather / [bot] / 裸插件名都认），空串 = 自己那段；key 空串读整段、否则按点路径取键。返回 JSON 文本，找不到就是 None
set_config(key, value_json) -> Result<(), AbiError>写自己的段。没有 section 参数——宿主按执行者身份判定，写不到别人那段。key 空串覆盖整段
set_config_for(section, key, value_json) -> Result<(), AbiError>写指定插件的段（跨插件同步设置）。section 同上；只接受 plugin.*，顶层归用户。规则与 set_config 一致

set_config 只写你自己那一个文件（<项目根>/plugin-config/<插件名>.toml，原子替换）， 不碰 fuyubot.toml——用户写在里面的注释、顺序、凭据都安全。三层优先级，以及「用户在 fuyubot.toml 里钉住的键会拒绝写」，见配置文件 · 插件自己的配置段。

编译与安装

define_plugin! 一个 crate 只能展开一次。一个 cdylib 就是一个插件——这不是限制，是设计： 七个导出符号名由 ABI 定死，展开两次就是重复定义。

要发消息、调 TDLib、等响应，见 调用 TDLib；要按字段过滤更新，见 订阅与事件；契约本身见 ABI 契约。
