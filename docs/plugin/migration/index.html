迁移到目录包

把平铺的 dll 和旧脚本插件改成 plugins/<id>/ 结构

旧版本把原生插件平铺在 plugins/*.dll，现在推荐一个插件一个目录：

平铺 dll 仍然能加载，但目录包才有静态元数据：plugin list 能显示版本、依赖、平台， 商店和安装器也能按 plugin.json 校验。新插件请直接用目录包。

先看现在是什么形态

输出会分成「目录包 / 旧平铺 dll / 脚本插件 / 已禁用」几段。只有旧形态需要迁移。

自动迁移

先空跑，确认它准备做什么：

确认后执行：

它会：

  • 对每个平铺 dll（带同名 .dll.disable 的也认）读取导出信息，取插件 id 和版本；
  • 新建 plugins/<id>/bin/，把 dll 和它旁边同名的依赖文件一起移进去；
  • 写一份 plugin.json；
  • 对旧脚本目录补一个 plugin.json（脚本本身不动）；
  • 内置插件和已经是目录包的插件跳过，重复执行不会重复迁移。

迁移完再跑一次 fuyubot plugin list，然后启动实例验证。

Go 编译的 c-shared 插件在迁移时会永久映射进当前进程，迁移进程随后退出，不会再卸载它。 这是正常现象；--dry-run 不会写文件。

验证

  • plugin list 里能看到目录包，版本、平台、依赖都对；
  • 回放 / 启动日志里没有 BundleNameMismatch、PlatformMismatch、EntryMissing；
  • 原来的命令、服务和配置段还能用。

回滚

迁移只是移动文件，没有改插件本体：

  1. 把 plugins/<id>/bin/ 里的 dll 和依赖移回 plugins/；
  2. 删掉 plugins/<id>/；
  3. 脚本插件删掉新加的 plugin.json 即可。

回滚前先停掉正在运行的实例。

常见问题

迁移后插件没加载

  • 平铺 dll 和目录包同时存在时，两个都会被扫到，可能重复注册。迁移是「移动」， 正常情况下不会同时存在；手工迁移时记得删掉平铺那份。
  • 检查 plugin.json 的 id 是否与 plugin_init 的名字一致。

提示 GoRequiresManifest

Go 插件没有 plugin.json 时加载器拒绝加载，因为 Go 的库一旦映射就不能卸载。 先迁移出 plugin.json 再启动；或者用 fuyubot plugin migrate 处理。

提示 platforms 不匹配

platforms 为空或 ["any"] 表示全平台；否则必须包含当前系统，例如 windows-x86_64、linux-aarch64、macos-aarch64。

脚本插件被当成原生插件

脚本目录要放在 plugins/scripts/ 下，不要放在 plugins/ 根上。

配置段还需要改吗

不需要。配置段仍是 [plugin.<id>]；迁移只改目录结构，不改插件 id。
