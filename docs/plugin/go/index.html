Go 插件

cgo 编 c-shared，逻辑用 Go 写、ABI 用一层 C 薄壳

Go 也能写插件：go build -buildmode=c-shared 出来的就是标准动态库，宿主只要看到四个导出符号 就认它。完整可跑的示例在 examples/go-ping。

目前没有 fuyubot-sdk init --lang go 模板——Go 这条路线是「自己搭工程」： 抄 examples/go-ping，或者照下面这两段写。C 头文件仍然用 fuyubot-sdk codegen --lang c --dir <工程目录> 生成，不要手抄。

编译

cgo 需要 C 编译器：Linux / macOS 用 cc，Windows 用 mingw-w64（如 w64devkit）。

Windows 上没装 mingw 时报 gcc: executable file not found 或 cannot open file 'mingwex.lib'——那是缺 C 工具链，不是插件代码的问题。 MSVC 的 cl 不能直接给 cgo 用（Go 的 Windows 外部链接器要 GCC 那一套）。

一个宿主行为要记住：Go 库不会被卸载

Go 的 c-shared 运行时有线程与信号处理器，FreeLibrary / dlclose 之后进程会直接 access violation（0xC0000005）。

所以 fuyubot-loader 会识别 Go 产物（文件里的 \xff Go buildinf: 魔数）， 故意不卸载这类库：plugin_stop 照跑、注册照回滚，只是那几 MB 库内存留到进程退出。 普通 Rust / C / C++ 插件不受影响，仍是 drop 即卸载。

这也意味着：别在同一个进程里反复加载同一个 Go 插件（热重载路径别指望它）。 先 fuyubot stop 再 run，行为是干净的。
