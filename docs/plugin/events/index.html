订阅与事件

on/off/emit、过滤器、双通道与归属

事件总线是插件拿到 TDLib 更新的唯一入口，也是插件之间说话的方式。三个动作： on 订阅（返回句柄）、off 退订（或让句柄 drop）、emit 发自定义事件。

双通道：具体 @type 与兜底 update

每条更新会被同时发到两条通道上：

通道谁收什么时候用
具体的 @type（updateNewMessage 等）精确订阅了它的监听器你只关心一种更新
"update"订阅兜底通道的所有监听器你要看全部，或不想追 TDLib 的类型名
"response"只发给发起那个请求的插件收 td_invoke* 的结果

"update" 与 "response" 是 ABI 常量（UPDATE_EVENT / RESPONSE_EVENT），别自己拼字符串。

过滤器

on 的第三个参数是一份过滤器 JSON：点分路径 → 期望值。

规则说明
event_type 键只用来选通道{"event_type":"response","request_id":5} 表示等 5 号响应；它不参与负载匹配
其余键做负载字段相等匹配字段位置随更新类型变：updateNewMessage 的 chat_id 在 message.chat_id
空 / null / 不传该通道全收

同一个事件可以订阅多次、各带各的过滤器。脚本侧按订阅号 handle 分发，所以不该响的回调不会响。

归属：emit 不是广播

插件里调 emit 走的是 emit_scoped(自己, …)：只送给该插件自己 + 全局订阅者。 归属的语义是「额外定向」而不是「排除广播」——宿主 emit 的更新照旧发给所有订阅者， emit_scoped(owner, …) 只是在那份收件人之外再加上 owner 自己的订阅。

谁发谁收得到
宿主发更新 / emit所有匹配的订阅者
插件 emit("x", …)该插件自己的订阅者 + 全局订阅者
宿主的响应emit_scoped(发起者, "response", …)：全局 + 发起者

要让别的插件收到你的事件，让对方订阅全局事件，不要指望你的 emit 是一次广播。

订阅句柄必须活着。Rust 侧 HostExt::subscribe_json 返回的是 #[must_use] 的 Subscription，drop 就是退订；let _ = … 会立刻退订。插件卸载时宿主还会整批回滚， 但那已经是另一回事了。

Rust

回调用 extern "C-unwind" fn(user_data, payload) -> i32，返回 0 表示成功；payload 是宿主临时的 NUL 结尾字符串，要留就当场拷走（parse_payload 已经替你解析成 serde_json::Value）。
