C 与 C++ 插件

同一份头文件、extern "C"、用你自己的工具链编译

C 与 C++ 用同一份头文件 fuyubot_plugin.h，差别只有两条：导出符号要不要放进 extern "C"， 以及用什么拼 JSON。头文件是产物，不是源码——它由 cbindgen 从 fuyubot-abi 的 Rust 定义生成， 权威副本是 fuyubot_abi::PLUGIN_HEADER，别手改。

C / C++ / Go 没有 async 运行时：请求与更新用回调（on），工具结果用 call_tool_result 同步拿。Rust 侧有 ResponseRouter（可 await），见 异步等待； 脚本侧有自己的异步写法，见脚本插件。

头文件

fuyubot_plugin.h 不在任何仓库里：fuyubot-abi 也不把生成物打进 crate，它是构建时产物， 每台机器现生成一次。三条路拿到它，任选一条。

一、用 build.rs 落盘（推荐，与 Rust 插件同一个来源）

头文件的内容就是 fuyubot_abi::PLUGIN_HEADER 这个常量（cbindgen 生成的原文），所以只要有东西 能编译 fuyubot-abi，就能把它落出来。build.rs 只是这一小步，不是把插件改成 Rust 写。

三、没有 Rust 工具链

头文件是纯文本，找一台已经构建过的机器、CI 产物或同事那里拷同一份即可，不用为此装 Rust。 前提只有一条：这份头文件的 ABI 版本必须与你机器上的 fuyubot 一致。

拿到之后

  • 校验版本：头文件里应是 #define ABI_VERSION 6（ABI v6）。对不上的旧头文件会缺 HostApiVTable 尾部字段，宿主加载时直接以 VersionMismatch / VTableTooSmall 拒绝——不会带病跑。
  • #include "fuyubot_plugin.h" 即可，C 与 C++ 共用；编译时用 -I 指向它所在目录（见下文「编译」）。
  • 不要手改：改 ABI 要改 fuyubot-abi 的 Rust 定义，头文件由 cbindgen 重新生成。
  • 不要提交：加进 .gitignore，升级 fuyubot / fuyubot-abi 后重新生成一次。

七个符号

v3 是四件套，v4 又加了三个（都可以不写，但写了才有对应能力）。

符号必须吗说明
plugin_init必须比 host->version != ABI_VERSION，存下 VTable，返回 PluginHandle
plugin_start可选订阅/注册；返回 0 表示成功
plugin_stop可选清状态；只登记元数据的插件可以不写
plugin_free_string必须释放本插件 malloc 出来的字符串（plugin_manifest 返回的那块也走它）
plugin_manifestv4 可选返回自描述 JSON（名字 / 版本 / inject / soft_inject），宿主在 init 之前读
fuyubot_abi_versionv4 可选静态返回 ABI_VERSION；宿主与静态检查工具不加载也能看到它
plugin_free_handlev4 可选ABI 版本不匹配时宿主靠它回收 init 分配的状态（那时不能调 plugin_stop）

PluginHandle 的判据是「abi_version != 0 且 context 非空」，所以 context 不能给 NULL。 版本不对就返回全零句柄，宿主会把它当成拒绝加载。

C

ABI_VERSION 与 FUYUBOT_EXPORT 都来自头文件，不要自己写死。

C++

同 C，唯一的硬差别是七个导出符号必须在 extern "C" 里——C++ 会改函数名（mangling）， 宿主按 ABI 定死的名字 dlsym，改了就找不到。

C-unwind 对 C/C++ 而言与普通 C 调用ABI 一致，但 C++ 的异常照样能穿过这个边界—— 逃到宿主那边的异常是未定义行为。在回调内部把异常处理完再返回。

手写 sendMessage（或者用 simplify_invoke）

手写 sendMessage 是另一条路——下面这些字段你都得自己拼对：

想要的效果手写的关键字段
纯文本input_message_content = inputMessageText，text 是 formattedText（text + entities）
Markdown / HTML不自己解析：先 td_execute 调 parseTextEntities（version: 2 = MarkdownV2），把返回的 formattedText 原样塞进去
回复某条reply_to = {"@type": "inputMessageReplyToMessage", "message_id": N}
发到话题topic_id = {"@type": "messageTopicForum", "forum_topic_id": N}
内联按钮reply_markup = replyMarkupInlineKeyboard；callback 的 data 是 base64
静音 / 保护内容在 options（messageSendOptions）里，不是顶层
等到「真发出去」请求号只到临时消息；要最终 Message 得再等 updateMessageSendSucceeded

要 Markdown 就分两步：先 td_execute 拿 parseTextEntities 的结果（一个 formattedText）， 把它的 text 与 entities 拼进上面的 input_message_content。方法名与字段名以 td_api.tl 为准（见调用 TDLib）。

注意

  • 模板里的 JSON 取值是朴素查找（strstr），不处理转义、不处理同名嵌套键；认真写就引一个 JSON 库。
  • 宿主返回的字符串是线程局部缓冲，只在下一次宿主调用之前有效——当场拷走，并且不要试图释放它。
  • set_config 只写 <项目根>/plugin-config/<插件名>.toml（原子替换），不改 fuyubot.toml； 用户在 fuyubot.toml 里写过的键会拒绝写（见 配置文件）。
  • 想少拼 JSON，可以只发 td_invoke_simplified 需要的参数对象（@type 由宿主补），见 调用 TDLib。
