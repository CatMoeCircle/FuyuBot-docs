三条硬门槛

⚠️ 三条都带 --workspace：根 Cargo.toml 有 default-members = ["crates/*"]， 裸 cargo build / cargo test 只编 crates/，不编 examples/。 #[allow] 不算消 warning——能改就改。

cargo tree --workspace --offline 必须无环；依赖方向随时能用 cargo tree -p <crate> -e normal --depth 1 验。

构建输入与缓存

td_api.tl 是构建的必需输入，fuyubot-tdlib-sys/build.rs 无条件去拿它：

缓存根按顺序找（build_support::cache_roots()，两个 build.rs 共用同一串）：

  • 仓里的 .cargo/config.toml 已把第三档指好（relative = true，相对仓库根），克隆下来直接能用。
  • 手写必须绝对路径：两个 build.rs 的 CWD 是各自的 crate 根，相对路径会解析到 crate 下面然后 404。
  • $OUT_DIR 每次重跑构建脚本都会被清空 → 退到它意味着下次重新下载，缓存根全写不进去时会明确警告。
  • 转换在编译期完成：日志里只有一条 已转换 …\td_api.tl：共 N 条。条数取决于那份文件，别当常量写进断言。

.cargo/config.toml 另有三个别名：cargo bot（= fuyubot run）、cargo package-bot、 cargo package-sdk（release 构建，产物在 target/release/，tdjson 由 build.rs 放到 exe 同级）。

两类测试

默认自检不碰任何外部文件：真 tdjson、真 td_api.tl（用 TDLIB_TD_API_TL 顶替时）、真 Releases 下载 全部藏在 #[ignore] 后面。所以「全绿」只证明代码自洽——与真实 TDLib 对不对得上只有那些 --ignored 能回答：

改 ffi.rs 的符号名/arity、loader::open_library（或任何加载动态库的地方）、 tl_schema / tl_codegen，或碰登录/授权代码之后，必须跑一次。 --features vendored 那条（会尝试访问 Releases，失败只警告）在动 build 脚本 / 资产表时也要跑。

测试写法的三条规矩

  • 临时目录不许用 %TEMP%：一律 target/test-tmp/<crate>/<名字>。MSYS 会把 TEMP 改成 /tmp， 受限环境里真实 %TEMP% 也可能写不了——换个 shell 就红的测试几乎总是这个原因。
  • 嵌套调用 cargo / 编译器时，把子进程的 TEMP/TMP 也指到那里：MSVC 的 link.exe 建不了 %TEMP% 里的 lnk*.tmp，直接 LNK1104，插件/夹具根本编不出来。
  • 非平凡逻辑留一个可运行自检：#[cfg(test)] 里一个 assert 测试即可，不引测试框架。

本机的离线约定

DSH 沙箱里 cargo 的 TLS 连不上 crates.io（schannel … SEC_E_NO_CREDENTIALS）。 Cargo.lock 已落盘，--offline 就够；只有改依赖版本时才需要联网，那时向用户申请一次完整权限跑 cargo fetch。
