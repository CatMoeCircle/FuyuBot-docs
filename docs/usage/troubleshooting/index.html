找不到 tdjson

构建成功不代表运行找得到：fuyubot-tdlib 在编译期不依赖 tdjson 存在。缺库时 run 不会崩，而是打一行然后继续跑（插件照样加载，只是收不到更新）：

四级查找顺序（不要重排）：

优先级位置
1TDLIB_TDJSON_PATH 指向的文件或目录
2vendored（构建期烤进去的目录）→ 可执行文件所在目录
3Linux 带版本号的系统库（libtdjson.so.1.8.68 …）
4裸库名（tdjson.dll / libtdjson.so，走 PATH）

报错里的 [1] … [4] 就是这四档的逐条结果，按顺序看就知道断在哪。嫌排查麻烦就直接指定：

加载动态库时会先查库自己所在的目录（Windows 上是 LOAD_WITH_ALTERED_SEARCH_PATH）。否则 tdjson 的兄弟依赖（libssl / zlib 之类）找不到，报的却是 ERROR_MOD_NOT_FOUND（126）——错误信息说「库不在」，实际缺的是它的依赖。所以 tdjson 和它的兄弟 DLL 要放在一起。

cargo install 装出来的二进制是唯一例外：安装目录不受构建脚本管，tdjson 得自己放到它旁边或设 TDLIB_TDJSON_PATH。

LNK1104: cannot open file '...\Temp\lnk{GUID}.tmp'

这是 MSVC 链接器写不了 %TEMP%（受限环境 / 沙箱里常见），跟你的代码无关。把临时目录指到可写的位置：

同一坑的另一面：测试不许依赖 %TEMP%。仓库约定临时目录一律放 target/test-tmp/<crate>/<名字>——MSYS（git bash）会把 TEMP 改成 /tmp（在 Windows 上解析成当前盘根），受限环境里真实 %TEMP% 也可能写不了。换个 shell 就红的测试几乎总是这个原因。

中文乱码 / 行号错位

本机 PowerShell 的默认代码页是 cp936：Get-Content 会把 UTF-8 当 GBK 解码，中文注释直接毁掉，还会吞换行导致行号错位（按行号删代码会删错）。看文件内容用编辑器或 read 工具，别用 shell 的文本通道读写源码。

脚本插件那条链路的 stdio 两侧已经钉成 UTF-8——Windows 上 Python 默认按系统代码页读管道，不钉就会把中文变乱码。这是 SDK 的职责，插件作者不用管。

插件加载失败

run 遇到加载不了的插件会打一行然后继续：

--plugin-dir 下的东西会被逐个尝试，所以「少加载了一个」不会让整个进程失败——去看这行。

现象原因 / 怎么查
ABI 版本是 N，宿主是 M插件与宿主的 ABI 不匹配：用同一份 SDK 重新编译，别拿旧产物硬跑
缺 plugin_init / 根本不是动态库fuyubot-sdk check <路径> 静态看导出符号；非零退出码 = 宿主一定拒绝加载
Node 报 Cannot find module '...\counter.ts'脚本同伴不在 cdylib 旁边。用 plugin install 装（会连 .py / .js / .ts / .pyi 一起拷），或把脚本和 dll 拷进同一目录
.dll 加载报找不到依赖插件把兄弟 DLL 放自己旁边是支持的（加载器先查库所在目录），别把它挪走，也别只拷主 dll

脚本插件还有一条硬约定：.py / .js / .ts 必须和那个 cdylib 同目录，宿主按「库旁边找脚本」的规则找它。

回放以非零码中止

多半是插件目录里有你不想要的东西：--plugin-dir 指向 target/debug 会混进所有示例产物，其中脚本插件的脚本不在旁边，加载失败就把回放整个拉停。把要验的插件装进一个干净目录即可。见 离线回放。

收不到更新 / 进程停不下来

现象处理
进程跑着但插件没反应没登录就收不到任何更新。要立刻验插件用 --replay
stop 之后进程还在stop 是写停止请求，实例每 500 ms 看一次；8 秒不理会才硬杀。硬杀跑不到 plugin_stop
终端里按了 Ctrl-C那是硬杀，不是优雅退出（捕获信号要开 tokio 的 signal feature，依赖白名单没放行）。要优雅就用 fuyubot stop

实例状态、锁与 status 的三种结果见 运行与实例管理。
