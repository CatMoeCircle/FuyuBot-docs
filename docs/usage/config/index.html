配置文件

fuyubot.toml 的字段与默认值

fuyubot run 读 fuyubot.toml，所有键都有默认值。缺这个文件时 run 会按模板自动生成一份（等价于先跑一次 fuyubot init）——--replay 是例外，它不会为了回放在你的目录里留配置。

一个项目目录长这样：

字段

键默认值它决定什么
[bot].namefuyubot显示名（启动那行、status 里的「名字」）
[bot].api_id0旧位置；[telegram].api_id 优先。新配置写进 [telegram]
[telegram].account_typebot登录走哪条路：bot → Bot Token；user → 手机号 / 扫码。写错报错，不会静默当 bot
[telegram].api_id0TDLib api_id（到 my.telegram.org 申请）。不是秘密；0 = 没配，run 会问
[telegram].data_dirdataTDLib 的数据目录：database 与 files 都指它。相对项目根
[plugins].dirpluginsrun 从这里加载插件（动态库 + scripts/ 下的脚本插件）；--plugin-dir 覆盖它
[plugins].log_levelinfo插件日志的最低级别：error / warn / info / debug / trace。排查插件时调成 "debug"；写错级别名会报错
[tdlib].path空留空 = 按四级优先级自动找 tdjson；指定时给 tdjson 的目录或文件路径
[tdlib].log_verbosity1TDLib 日志详细度。TDLib 自己的默认更啰嗦（每轮 td_receive 的超时都打到 stderr）；负数按 0 处理

模板（fuyubot init 生成的就是它）：

凭据一律不落盘：api_hash、Bot Token、手机号、验证码、两步验证密码都不许写进配置文件（连日志也不行）。api_hash 在配置里根本没有字段，写了也会被 serde 忽略——它只认环境变量 TG_API_HASH 或 fuyubot run 的交互式输入。session 由 TDLib 自己落在 data_dir，配置里不记任何登录态。

几条约定

  • 相对路径相对配置文件所在目录（也就是项目根）：plugins、data、日志目录都按它解析。
  • 自动 init 只认默认文件名：缺 fuyubot.toml 时 run 会生成一份；但用 --config 别的名字 时不会凭空造，直接报错。
  • status / stop 不替你造配置：找不到 fuyubot.toml 就报「先 fuyubot init 建一个」——面对的是已经存在的实例，凭空建一个只会更迷惑。
  • --plugin-dir 覆盖 [plugins].dir，--config 换配置文件本身。
  • 想知道某一行到底生效成了什么（含默认值）：fuyubot config 直接打出来，见 fuyubot 命令参考。
  • 字段读出来后，运行参数（凭据来源、加载顺序）见 运行与实例管理；account_type 之外没有别的自定义登录入口。

改了配置怎么生效

配置在 run 启动时读一次。改完要重启实例：

--replay 不占单实例锁，所以它可以和跑着的实例并存、跑完就退，适合改插件期间反复试。

改完先别急着重启：fuyubot config --config demo\fuyubot.toml 会打印生效值，account_type 之类写错时当场就能看出来（那一行是 ⚠️ 开头，而 run 要走到登录才报）。
